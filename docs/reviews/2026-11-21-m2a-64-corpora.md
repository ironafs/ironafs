# Review record: published conformance corpora in `docs/specs/README.md`

## The change

Class P. Issue #64 (plan id M2a-86). The owner decided that published
conformance corpora for mainstream cryptography may enter the tree as a
separate conformance layer. This change writes the rules for them in
`docs/specs/README.md`, "Published conformance corpora":

- what qualifies: mainstream cryptography only, published as conformance
  material by a standards body or a conformance project, never from an
  implementation's source, and with its licence settled;
- licence and provenance before the files enter: the terms read at their
  source with a CONFIRMED or UNVERIFIED verdict, the licence on ADR 0001's
  allowlist or the owner's decision, the licence text in `LICENSES/`, a
  `REUSE.toml` annotation, a `docs/provenance.md` row and every notice the
  licence requires;
- one pinned version per corpus, unmodified, in
  `crates/<crate>/tests/conformance/<publisher>-<set>/` with a
  `SOURCE.md` manifest;
- how a specification cites a corpus: never as a golden vector, never as
  a source of requirements, never as the only check of a requirement;
- how tests run it: every vector run or skipped by a written rule, counts
  checked against the manifest.

**Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent).

## Findings

Gemini, round 1. Each minor is fixed in the commit that adds this record,
on top of `ea78e66`:

- **Minor, fixed: placement across specification kinds.** The corpus
  heading went "after the reject corpus", and the specification's own
  tests were listed as golden vectors and property tests, but only
  `protocol` and `format` specifications have those; a `behaviour`
  specification has acceptance cases. The README now says "the crate that
  owns the format or interface", places the heading after the acceptance
  cases where a specification has no reject corpus, and counts acceptance
  cases among the specification's own tests.
- **Minor, fixed: `LICENSES/` for an UNVERIFIED corpus, and the
  `REUSE.toml` scope.** A corpus the owner admits with an UNVERIFIED
  verdict may have no publisher statement to put in `LICENSES/`. Its
  `LicenseRef-` file now holds what was found (the statement as
  published, or a line saying none was found, with the locators and the
  date) and the owner's decision with its date. The `REUSE.toml`
  annotation now covers the corpus's files and notices, not `SOURCE.md`,
  which carries its own header.
- **Minor, fixed: where the second reading and the digests are
  recorded.** The second, independent reading of a transcribed corpus was
  recorded only in the pull request. It is now recorded in `SOURCE.md` and
  in the change's review record. The manifest's SHA-256 digests now cover
  the document a transcription was read from and the transcribed file.
  The test checks each vector file's digest against the manifest before
  reading it, and the run, count and parse rules now apply to vector
  files, not to kept `NOTICE` files.
- **Minor, fixed: licence re-check on a version update.** A new version
  now repeats point 2: the terms read again, the notices checked, and any
  owner's decision taken again for that version. A published crate that
  leaves a corpus out of its package now leaves out the conformance tests
  that read it too.
- **Minor, fixed: policy-dependent labels.** A vector whose expected
  result the corpus leaves to the implementation's policy (Project
  Wycheproof's `acceptable`) is run, and the test asserts the one result
  IronAFS's specification requires, by a rule that cites the
  specification's point. It never passes on either result.

Gemini also listed what it could not check, since only the README and the
diff were inlined: the wording of ADR 0001's sections, ADR 0004 C5 and
coding standards rules 15, 20 and 21, the specification template,
`docs/provenance.md`, `REUSE.toml`, `deny.toml` and `xtask`, and the
workflow's classes. The author checked the citations by hand: ADR 0001's
sections "Test tools and test data", "Third-party material that is copied
in" and "Releases", ADR 0004 C5, and rules 15, 20 and 21 exist and say
what the README cites them for.

The review stopped there, under the stop rule: only minor findings, fixed
and recorded, so no verification round.

## Open for the owner

These are licence questions for the first corpora (M2a-67), not decided
here. Under these rules each corpus waits for the owner's decision if its
verdict is UNVERIFIED:

- **NIST CAVP files** (the SHA-256 vectors): whether NIST's statement on
  its works covers these files as published, and whether that holds
  outside the United States.
- **RFC 4231 test values** (HMAC-SHA-256): whether the copyright statement
  of an RFC published before the IETF Trust's current licence covers
  values transcribed from it.
