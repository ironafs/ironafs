# Review record: `ironafs-os`, Linux part, first pull request

## The change

Class S. Issue #57 (plan id M2a-09), part A of five. Part of #57.

- `crates/ironafs-os`, the one crate ADR 0005 lets hold `unsafe`: its own
  lint table (the workspace's with `unsafe_code = "deny"`, point 1.5), no
  dependencies, and a target guard (a `compile_error!` outside the
  allowlist of point 5.3).
- Three sites of ADR 0005's table, each a safe API with a named
  `#[expect(unsafe_code)]` and a `// SAFETY:` argument:
  - `linux-clock` (row 1): `read_clock(OsClock::Boot | Awake)`, from
    `CLOCK_BOOTTIME` and `CLOCK_MONOTONIC`;
  - `linux-random` (row 8): `fill_random`, the raw `getrandom` system call
    through `syscall`, every variadic argument a `long`, 256 bytes a call,
    `EINTR` retried, `ENOSYS` and `EPERM` "unavailable or filtered" with
    the real errno, no fallback;
  - `mem-wipe` (row 24): `wipe`, a volatile zero write per byte.
- Under Miri each foreign call is replaced by an in-crate stand-in with
  its signature (point 6.5).
- `crates/ironafs-os/sites.json`, the machine-readable copy of the ADR's
  table (all 24 rows), and three checks:
  - `cargo xtask check-os`: no `unsafe`, foreign item or `#[link]`
    outside the crate; per target, the sites the compiler read equal the
    copy's implemented rows; the copy bound to the ADR's own rows; the
    guard evaluated against every target the pinned compiler knows;
  - `cargo xtask check-abi`: C11 assertions generated from the Rust
    declarations, compiled with the target's own C compiler and headers
    (point 5.6);
  - `check-deps`: `ironafs-os`'s lint table, and no dependency of any
    kind.
- CI: per-target Linux lanes (Ubuntu 24.04 and 26.04, x64 and arm, glibc
  and musl), a glibc 2.28 lane, and a Miri job.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## Open items

Each quotes GPT's round-3 finding and says what would close it.

The literal reader at line 333 also forwards leading-zero Rust decimals as C octal literals. I confirmed that Rust reads `046` as 46 while C reads it as 38." Closes with: derive the required C facts
  from the compiled Rust or from the approved row rather than from the
  editable copy, reject a shadowed `core`, and emit constants as
  normalized decimal values; plants for a missing fact, shadowing and a
  leading zero.

The syscall rule checks operand count only." Closes with: bind the wipe to the
  unshadowed `::core::ptr::write_volatile` and the `syscall` operands'
  types at the call; a paired plant that keeps the last path segment.
