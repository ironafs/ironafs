# Review record: the node table, node identity and aliases

## The change

Class S. Issue #91, its first part: the node table of ADR 0004, C11, in
`ironafs-cache`, under the namespace specification's rules for node
identity, anchors, bindings and retention (5.6.1 to 5.6.4). The branch
starts from #71's types branch and merges #67's contract crate
(`8f66e9a`), which is the base of the reviewed range.

- Identity types: `CellIndex`, `VolumeId`, `Vnode`, `Uniquifier`,
  `FileId`, `PathKind`, `Version` and `ContextKey`.
- `MountChain`: a root's anchor chain, inline in its record, at most 32
  mount points, depth checked before repeats.
- `NodeTable`: ids from 1, never reused, refused at `u64::MAX`; keys for
  entry nodes and for file id plus anchor; per-context bindings from a
  mount-point or entry node to a root node, with the chosen version kept
  only in the binding; the reverse index of aliases and volumes; retention
  while named or held; eviction of the oldest unheld, unnamed node;
  per-context charges, refused as busy over budget or in a full table.
- Integration tests: the issue's acceptance cases, a property test against
  a reference model, and an exhaustive sweep of every three-operation
  sequence of a small domain.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent),
  the first version and the fix.

## Findings

### GLM

- **Minor** (origin: pre-existing; kind: contract): `cross` made the root
  record, and in a full table evicted a victim, before the budget and
  context-count checks ran. A refused crossing left a node no context
  entered, its alias, and possibly an evicted entry. No test reached the
  path: the model always crossed with a budget of 64. **Fixed** in
  `4fd3db0`. Every check runs before the root is made: a new root's
  closure is itself plus what its anchor holds. Tests:
  `cross_refused_over_the_budget_leaves_the_table_unchanged`,
  `cross_refused_over_the_context_limit_leaves_the_table_unchanged`. The
  model now draws a budget for each crossing, and checks that any refused
  operation leaves the table's size and every charge unchanged.
- **Minor** (origin: pre-existing; kind: correctness): a rebinding held
  the new root before it released the old one, so a context at exactly
  its budget could never move an anchor to another volume, even though
  the charge after the move would fit. **Fixed** in `4fd3db0`: the budget
  check compares the net charge after the old root's hold is dropped. The
  new hold is still applied before the old one is released, so a refusal
  keeps the old binding. Test: `rebinding_at_the_budget_is_charged_the_net`.

### DeepSeek

- **Minor:** the same as GLM's first. Fixed with it.

All three new unit tests, and both model tests, fail on the code before
`4fd3db0` and pass on it (EXECUTED, development Mac).

### Uncertain items, and what was done

- Node ids restart at 1 in each table, and C11, point 2 asks for
  uniqueness within a daemon instance (DeepSeek). The daemon keeps one
  table for its life. The table's documentation now says so; the
  composition crate is where it is kept.
- The chain is held behind one `Box` per root record rather than in the
  record itself (GLM). The namespace specification's purpose holds: one
  record read, fixed capacity. Recorded as a named departure in the pull
  request.
- C11, point 1 names the anchor as "the dynamic root, a cell root, or a
  mount point". The table anchors a cell root at its dynamic-root entry
  node, as the namespace specification, 5.6.3, point 5 says (GLM). No
  change.
- A crossing of volume 0 is refused with `VersionAbsent` before the depth
  and cycle test (DeepSeek). A compliant caller never reaches both, and
  each refuses. No change.
- Which context holds a file for a break, and the per-context break
  counters, are the callback service's and a later part of #91 (DeepSeek).
- The namespace specification's containing-version and
  authenticated-location rules (5.6.2, points 9 and 10) are the crossing
  code's, outside this crate. The table exposes `binding`, `kind` and
  `containing_root` for them (DeepSeek).
- Neither seat could run cargo or read the issue. Execution evidence is
  the implementer's, below.

## Open questions

- The contract gives `pin` a node and no caller, while C11, point 10

  `child` refuses a known file under another parent (`ParentChanged`) and
  changes nothing until this is decided.
