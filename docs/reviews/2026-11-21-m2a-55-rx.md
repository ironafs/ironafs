# Review record: the Rx transport and null class specification

## The change

Class S. Issue #55 (plan id M2a-02). This is the first version, written
from documents only; the issue stays open for the capture-backed
revision (rx.md, section 13, Q1).

- `docs/specs/rx.md`: the Rx packet header and types, their caps,
  decoding and encoding; connections, wire identity, channels, call
  numbers and serials; the call lifecycle, acknowledgements,
  retransmission, flow control, keepalive and timeout; the
  security-class interface with the rekey request and the "key
  exhausted" outcome, and the null class; unprotected ABORT, BUSY,
  CHALLENGE and ICMP as ADR 0006 decides; the server role the callback
  service needs (admission, caps in bytes per peer and in total, the
  overload event and its confirmation, the pause and its generation,
  the unverified-source budget); counters, events and a bounded event
  queue; the interface between the pure machine and the driver; tests.
- `docs/specs/README.md`: register rows E3 (the Rx draft, as read for
  this specification) and E4 (RFC 4291).
- **Written by** `claude-code:claude-opus-5-5` (drafting, and the fixes
  of every round).
- **Merge order.** The specification cites ADR 0006, which is accepted
  and lands with pull request #102. This change merges after #102, so
  that its links to ADR 0006 resolve on `main`.

## Findings

### Round 1

GLM and DeepSeek raised the same top finding: an incoming call whose
request was complete but whose reply went unacknowledged had no
deadline, and a service's reply cap had no ceiling and no charge.

- **Blocker (DeepSeek) and major (GLM), fixed:** the incoming call's
  reply phase. New caps `rx.in.reply_deadline` (60 s from the complete
  request) and `rx.in.reply_ceiling` (65 536 bytes); reply bytes are
  charged to the peer and the total; a reply over the cap or the charge
  is refused at submission; a matching ABORT on a complete incoming
  request ends the call (5.7, point 14; 5.9, point 6; 5.10, points 1,
  2 and 7; A23, A26).
- **Major (DeepSeek), fixed:** a call's queued sends survived its end.
  The machine now removes every queued DATA packet and PING of a call
  when it ends (5.12, point 4; A4, A15, fuzz target 2).
- **Major (DeepSeek), fixed:** a credential change had no send-time
  guard for a RESPONSE (ADR 0006 D1.3). The user raises the permit
  generation on a credential change too, so the one check at the driver
  seam covers it (5.9, point 3; 5.12, point 4; A8).
- **Major (DeepSeek), fixed:** no ceiling for a service's reply cap
  (with the first finding).
- **Minors (GLM), fixed:** the reachability PING's size contradicted
  "all four trailers are sent" (5.5, point 4 now names the exception);
  the keepalive call had no rule when no unused channel was left
  (`StartRefused`, 5.6, point 3; A18); A9 did not carry ADR 0006 test 9
  in full (rebinding, restart and the refusal cases added).
- **Minors (DeepSeek), fixed:**
  - the BUSY deferral cap omitted its half-the-time clause (5.9, point
    7; A7);
  - the SACK loop bound underflowed for N = 0 (5.7, point 6);
  - the encoder's refusal list was incomplete (5.5, point 9);
  - fuzz target 2's "nothing sent" property was false for an opening
    packet;
  - P3 could not hold for fields the encoder owns (restricted to the
    form 5.5 produces);
  - `ChallengeReceived` was emitted before the class check (5.11);
  - a held datagram's charge to its peer contradicted 5.10, point 2
    (now charged to the held allowance and the total only, with the
    one-source pause stated as a residual in section 8);
  - the drop table's retention rule was unstated (5.9, point 4);
  - the first call number of 1 was attributed to the draft, which only
    requires a positive value; it is ADR 0006 item 4's fallback (5.6,
    point 3);
  - ADR 0006 tests 7, 9 and 13 were not carried exactly (A7, A9, A16);
  - a DATA payload over `rx.payload_max` after the class had no counter
    (`data_too_long`, R15);
  - "four times" the default window was twice;
  - the draft was quoted directly, against register row E3 (paraphrased;
    a second quoted phrase was found and paraphrased too);
  - the IPv4-mapped prefix had no source (RFC 4291 §2.5.5.2, register
    row E4);
  - ICMP hints and the event stream were unbounded (5.9, point 9; 5.11).
- **Uncertain items:** DeepSeek's note on the direction field, the
  layer that holds request bytes, and A10's latency bound were fixed;
  its note on the ignore-source bit was recorded in section 13, Q4; its
  note on a peer's PING-RESPONSE size was refuted (the unverified
  budget is cumulative per connection). GLM's notes were recorded
  without change, except the resume wording, which was clarified.

### Round 2

- **Major (DeepSeek), fixed:** the event queue's bound on keys was false
  for calls, because a peer chooses call numbers and can open and end
  calls cheaply. The queue now has a byte cap, `rx.event_queue_bytes`,
  with fixed reserved slots, a counted overflow (`EventsDropped`), and
  call-level events keyed by connection; call outcomes never pass
  through it (5.11; A26 drives 10 000 calls on one connection).
- **Minor (GLM and DeepSeek), fixed:** merging was undefined for events
  that carry no counts; a per-kind merge table now states it.
- **Minors (DeepSeek), fixed:** the keepalive exception was missing from
  5.7, point 1 (one of its two states was refuted: a busy channel has
  always carried a call); `rx.in.peer_bytes` was below one call at both
  ceilings (raised to 262 144 bytes); a held datagram could fail the
  total (the held allowance is now kept free inside it); a report could
  zero ICMP counts no event had carried; send actions did not name their
  call; "never a dropped break" overstated the pause (now: none before
  its server's suspect epoch has moved).
- **Minor (GLM), fixed:** a BUSY waiting on the unverified budget had no
  end; ACK, BUSY and ABORT packets that do not fit are now skipped.
- **Uncertain items:** six of DeepSeek's were fixed (a reply after the
  call ended, `sent_any` after the purge, the allocation claim, A9's
  redraw budget, the ICMP key, and the test 3 mapping in 10.5).

### Round 3

All fixed in `5becb07`:

- **Minor (GLM):** the event table's Carries column did not list the
  fields the merge table uses; it now does.
- **Minor (DeepSeek):** `AbortHint` and `AbortReceived` could be refused
  for room, although they carry the `eligible` flag ADR 0006 D1.6
  depends on. On an outgoing connection they now take reserved slots,
  bounded by keeping the connection's identity reserved, against
  `rx.identity_bound`, until the user takes the event.
- **Minor (DeepSeek):** a refused `IcmpHint` or `DropCounts` left the
  counting rules ambiguous; their counts are now deferred to the next
  queued event, never lost.
- **Minor (DeepSeek):** a sentence in 5.10, point 5, named the wrong
  datagram.
- **Minor (DeepSeek):** A11 still used the whole total, not the total
  less the held allowance.

Both lanes' remaining uncertain items are open notes for the callback
service's specification (#66): the policy that confirms overloads and
ends a pause, and repeated revalidation under a sustained flood from
one source. Neither changes what Rx does.

## Clean room (ADR 0001)

- The only source for Rx is the community draft (register row E3). It
  was read only as a copy with its section "Historical Implementation
  Notes" removed mechanically before reading; that section was never
  read or cited.
- The first version was written from that copy, read in full. Fix round
  1 searched it for three phrases and re-read its "Rx Connections"
  passage on call numbers (23 lines) to check one finding. Fix rounds 2
  and 3 read none of it.
- No implementation's source, test data or interface definitions were
  read. The specification names no file, function, structure or
  identifier of another implementation, and quotes no text of the
  draft.
- The review lanes were not given the draft, ran with no web access,
  and did not fetch or open it.
- RFC 4291 was read at the RFC Editor for §2.5.5.2 only.
