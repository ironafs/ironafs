# Review record: the seam interface types and `check-seams`

## The change

Class S. Issue #71, its second part: the interface types of
`docs/specs/seams-and-scheduling.md` in the crates it names, and the two
`xtask` checks that keep its source rules. The branch is stacked on
#113's branch (`m2a-71-seams`, the specification), whose head `9fa32da`
is the base of every range below.

- `ironafs-time`: `Clock::sample` and `Clock::wait`; `Doubt`, `Stamp`,
  `Deadline` (private fields, two pure constructors), `DeadlineError`,
  `Waited`, the `Watch` and `Waker` traits, `WatchRef`, `Registration`,
  `WatchFull`; its own `clippy.toml`.
- `ironafs-test-support`: the seeded clock's `sample` and `wait`, its
  doubt and episode counts, and `regress`.
- `ironafs-rx` and `ironafs-cache` (new pure crates): the `Rpc` and `Disk`
  traits and the values they carry, `StorePath` with its validated names,
  and plans.
- `xtask`: `check-seams [--self-test]` (`pure_crate_calls_no_seam` and
  `deadline_built_from_a_fresh_sample`), run by `cargo xtask check` and by
  CI; `check-bans` gains the two `Deadline` constructor bans (the
  specification's second net) and keeps `ironafs-time`'s `clippy.toml`
  equal to the root one without them; `metadata` reads the names a member
  gives its dependencies.
- `docs/specs/seams-and-scheduling.md`: a scoped amendment of 5.2, point
  5, 5.3, point 2, and section 9, so the page states the checks as built,
  with their limits. Its status line says what was amended.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent),
  the first version and every fix round.

## The stop decision

After round 3 the stop rule was hit (two fix rounds, and a full round
after each). GLM passed rounds 2 and 3. DeepSeek's round-3 major narrowed
each round: from a seam reached through an uppercase alias (round 1), to
name collisions with home-crate enums (round 2), to renames the manifest
text scan could not see and a scope-blind variant set (round 3). The
controller chose one minimal structural fix and no further round: read
renames from cargo's resolved graph, which closes every manifest spelling
at once; refuse `path = ...` inside `cfg_attr`; and state the
specification amendment exactly as the code behaves. That fix is
`df44e3d`. **It was made after the final verification and has not been
re-reviewed.** `AI-Reviewed-by` credits GLM only, whose last verdict is a
PASS; DeepSeek's last verdict is a FAIL, and its last major is addressed
by `df44e3d` without review.

## Findings

### Round 1, GLM (fixed in `009b2ad`)

- **Major:** the fresh-`now` rule matched by name, so a parameter or a
  shadowing binding named `now` passed. Fixed: the binding's name may
  appear only as the constructor's `&now` after its `let`.
- **Major:** the enum-variant exemption exempted any seam name after an
  uppercase segment, so `use ironafs_time as Time; Time::Clock` passed.
  Fixed: exemption only through an enum that declares the variant;
  renamed and glob imports of a home crate refused.
- **Minor:** the specification's second net (the constructors on clippy's
  ban list) was missing. Fixed by the controller's decision: both bans in
  the root `clippy.toml`, `ironafs-time`'s own file without them, kept in
  step by `check-bans`, whose canary now proves both bans fire.
- **Minor:** the `Clock` doc example reported an undecided wait as passed.
  Fixed: it keeps waiting.

### Round 1, DeepSeek (fixed in `009b2ad`)

- **Major:** the same alias exemption as GLM's. Fixed with it.
- **Major:** CI never ran `check-seams`. Fixed: it and its self-test are
  CI steps beside the other checks.
- **Major:** `ironafs-time` itself was unguarded (a helper there could
  hand the constructors out). Fixed: the second net, and `check-seams`
  now reads `ironafs-time`, where the constructors' names may appear only
  at their definitions.
- **Minor:** the constructor's `from` was not bound to the `from`
  parameter. Fixed.
- **Minor:** `MAX_COMPONENTS` and `MAX_NAME_BYTES` were not named as
  additions. Fixed in the pull request text: they stay public, and their
  values are this change's choice.
- **Minor:** a `#[path]` module or a `tests.rs` under another name could
  hide source from the walk. Fixed: `#[path]` refused.

### Round 2, GLM (PASS; minors fixed in `2ac4abb`)

- **Minor:** the seeded clock judged a regression against the last value
  any read returned, not the last valid sample (5.3, point 2). Fixed.
- **Minor:** `include!` was not refused. Fixed.

### Round 2, DeepSeek (fixed in `2ac4abb`)

- **Major:** the variant exemption was still a name match across crates:
  an enum named like a home crate with a `::`-rooted path, or a Cargo
  rename to a home enum's name, let a seam through. Fixed: paths resolved
  by segment (`::Owner::Name` refused; a home enum only by the crate's
  name or a named import), items named like a home crate refused, and
  manifest renames refused (by a text scan; see round 3).
- **Minor:** the self-test accepted any violation, so a plant could pass
  for the wrong reason. Fixed: each case requires its own kind, on its
  planted line where that kind has one.
- **Minor:** the specification was stale about the checks. Fixed by the
  first amendment.
- **Minor:** the `.sample()` receiver was not bound to the `Clock`
  parameter. Fixed: it must be a parameter whose type names `Clock`.

### Round 3, GLM (PASS; minor fixed in `df44e3d`, not re-reviewed)

- **Minor:** the manifest scan missed a dotted-key rename
  (`DeadlineError.package = ...`). Fixed by reading renames from cargo's
  resolved graph.

### Round 3, DeepSeek (FAIL; addressed in `df44e3d`, not re-reviewed)

- **Major:** renames still slipped through the manifest text scan (quoted
  and dotted keys, a rename inherited from the workspace's dependency
  table), and the crate-wide variant set then exempted `Owner::Name` for
  an out-of-scope local enum named like the rename. Addressed: any
  dependency of a pure crate whose name in cargo's resolved graph differs
  from its package's name is refused, whatever its spelling. The variant
  rule stays name-based; the amended specification says so, and why the
  refusals make it enough: with renames refused, a crate is named only by
  its package's name, an item named like a home crate is refused, and no
  module can re-export a seam without writing its name.
- **Minor:** a `path` inside `cfg_attr` was not seen. Fixed.
- **Minor:** the amendment was not exact against the code. Addressed: the
  amendment now states the name-based variant rule, the `::`-rooted home
  path it allows, the textual `Clock` parameter test (a generic `C: Clock`
  is refused), the `|` rule, which plants are judged by kind alone, and
  that a manifest `[lints]` table cannot carry an allowance (`check-deps`
  requires every member to inherit the workspace's lints).

### Not raised as findings, or left as they are

Both seats ruled these acceptable:

- The seeded clock's doubt and episode counts saturate rather than fail at
  2^64, which no use of its API reaches.
- Its `wait` advances all three clocks by the time left on the deadline's
  clock.

## Recorded limits

These are written in the specification and stay as limits:

- Both checks read source as written and expand no macro: a macro that
  assembles a constructor's path, a `path` attribute or an `include!`
  from fragments is not seen.
- The call-site check trusts that only the ingress writes a request's
  `arrival` and only the call owner a reply's `first_sent`. The self-test
  records an equal-count forged `from` through each as a pass.
- The variant rule matches names, not scopes. Its false positives (a type
  alias of a home enum, a home enum re-exported through a local module,
  `Self::Name` outside the declaring file) are refused and rewritten.
- The `Clock` parameter test is textual: a different trait named `Clock`
  is not told apart.
