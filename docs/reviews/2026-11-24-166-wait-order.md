# Wait observation order (#166)

Class S. The [seams specification](../specs/seams-and-scheduling.md)
requires cancellation, a signal snapshot and then a clock observation.
The observation order makes the `Signalled` result meaningful without
giving the wait authority over the result owner's publication.

`SeededClock::evaluate` keeps the outcome priority and uses the same
locked clock-and-doubt pairing as the adjacent clock methods. The new
`Watch` uses the passive test flag's registration stubs and atomic
observation style. Its deliberate additional effect is to advance the
clock on first observation. The two tests reuse the existing clock,
deadline and doubt helpers. The independent consistency check found
the same six functions.

The controller compared the full 5.3 point 3 across the two commits and
confirmed it is byte-for-byte unchanged. The result-owner reference is
backed by 5.4 point 4, with the failure-versus-success rule in ADR 0004
C46 point 4. Neither a production nor a simulator blocking wait is
introduced. The wake between a false snapshot and the generation recheck
belongs to the first production blocking wait's conformance test.
