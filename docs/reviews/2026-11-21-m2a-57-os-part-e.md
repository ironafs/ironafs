# Review record: `ironafs-os`, Linux part, part E

## The change

Class S. Issue #57 (plan id M2a-09), part E, on top of parts A, B and C
(branch `m2a-57-osc`, merged at `a8f20f6`). Part of #57.

- **The sites (ADR 0005, rows and sheets 21 to 23):**
  - `linux-udp6` (row 21): `udp6_socket(Ipv6Addr, u16)`.
    - It makes an IPv6-only, close-on-exec UDP socket as a `std::net::UdpSocket`.
    - The calls are `socket`, then the adoption as an `OwnedFd`, then `IPV6_V6ONLY` set to 1, then `bind`.
    - An address that needs an interface zone (`fe80::/10`, and multicast of interface- or link-local scope) is refused before any call.
    - `EAFNOSUPPORT` and `EADDRINUSE` are errors of their own.
  - `linux-statvfs` (row 22): `available_space(BorrowedFd)`.
    - The descriptor is checked to be a directory's first.
    - Then `fstatvfs`, with `EINTR` retried.
    - The answer is `f_bavail × f_frsize`, overflow checked.
  - `linux-rtnetlink` (row 23): `RouteSocket::{notify, request}`, `send` and `receive`.
    - The notify socket joins the owner's group set; the request socket joins none.
    - A send names only the kernel.
    - A receive is returned only if all of these hold: the sender's address is exactly `struct sockaddr_nl`'s length, of family `AF_NETLINK`, and port id 0 (in that order, the port read last); and no `MSG_TRUNC` is set.
    - `ENOBUFS`, truncation, a malformed sender and a sender other than the kernel are distinct errors.
    - Nothing is decoded here.
- **Checks:**
  - `check-abi`:
    - reads array members (`[T; N]`, checked by element type and count);
    - accepts an opaque struct tail only where its own allowlist, `OPAQUE_TAILS`, approves it, bound to where the C member before it ends and to its length;
    - parses `expressions` for balanced parentheses and the operators `* + - | << >>`.
  - `check-os`:
    - binds an `OwnedFd::from_raw_fd` adoption to a row that says its descriptor is adopted as an `OwnedFd`;
    - requires exactly one adoption where a row says "one that adopts".
  - The computed lengths (`sizeof(int)`, `sizeof(struct sockaddr_in6)`, `sizeof(struct sockaddr_nl)`) and the notify group mask are proved as C expressions on glibc and musl.
- **Tests:**
  - every wrapper's calls, retries and errnos run through Miri stand-ins, and each stand-in refuses a call it does not model with `EINVAL`;
  - kernel tests run in the guest and in CI;
  - the netlink tests that need `CAP_NET_ADMIN` run in a network namespace of their own, one at a time;
  - the statvfs tests' exact readings use a dedicated tmpfs and an ext4 that reserves blocks;
  - the udp6 tests run at `net.ipv6.bindv6only` 0 and 1, and under an address-family filter.
- **CI:**
  - the os-linux lanes prove the three sites per target;
  - musl's lanes add the kernel's own headers to `musl-gcc`'s path;
  - new steps cover the statvfs mounts, the udp6 namespace runs, the systemd sandbox, and the rtnetlink namespace;
  - the glibc 2.28 lane now runs check-abi and requires every site's named native tests;
  - the Miri job names the new tests.
- **Written by** `claude-code:claude-opus-5-5` (Claude Code subagent,
  test first).

## Findings and their last state

GLM, round 1:

- **GLM1, major: refuted, the refutation accepted by GLM in round 2.**
  - Finding: "RTNLGRP_IPV6_RULE is declared as 19, but the kernel's <linux/rtnetlink.h> (the header sites.json names, from linux-libc-dev on every CI lane) defines RTNLGRP_IPV6_RULE = 13: the RTMGRP_* masks confirm the enum order through group 12 (RTMGRP_IPV6_PREFIX = 0x800), the IPv6 rule group immediately follows (13), and group 19 is RTNLGRP_IPV6_NETCONF. So NOTIFY_GROUPS = 263_633 (bits for groups 1,5,7,8,9,11,19) should be 5585 (groups 1,5,7,8,9,11,13)."
  - Evidence:
    - The header (Debian linux-libc-dev 6.12.100-1) has `RTMGRP_IPV6_IFINFO` = 0x800, which is group 12, and `RTMGRP_IPV6_PREFIX` = 0x20000, which is group 18. Its enum places `RTNLGRP_IPV6_RULE` after `RTNLGRP_IPV6_PREFIX`, so it is 19.
    - A C file asserting `== 19` and `!= 13` compiles with glibc's `cc` and with `musl-gcc`.
    - Planted 13, `check-abi` fails on both with "static assertion failed: linux-rtnetlink: RTNLGRP_IPV6_RULE".
    - The namespace test matches the IPv6 rule's add and delete on the notify socket.
  - GLM, round 2: "REFUTATION ACCEPTED".
- **GLM2, minor: fixed (`3a52fd2`), confirmed by both seats.** Finding: "The widened `expressions` alphabet accepts `- | < >` alongside parentheses without requiring them balanced, so an expression string such as `1) || (0` closes the generated _Static_assert((EXPR) == VALUE, ...) early and turns the condition into the tautology ((1) || ((0) == VALUE)), which compiles and passes for any Rust constant value."

An expression can close its generated wrapper and make the static assertion true independently of the expected value. I confirmed the resulting assertion compiles as C11 with warnings treated as errors."
