# Review record: ADR 0005, `ironafs-os`, and the ADR 0004 C5 amendment

Issues #43 (ADR 0005) and #49 (the ADR 0004 amendment). Class S. The ADR
was written by Claude Code (`claude-opus-5-5`) for the maintainer, with
decisions taken by the owner on 2026-11-20. It was reviewed as private
drafts before publication, so rounds 1 to 14 each name the frozen copy
they read by SHA-256 in the lane's own output, not by a commit. Rounds 15
to 17 read commits on the pull request's branch, named in their entries.

## Rounds 1 to 6 (GPT)

- **Round 1, design review:** FAIL, 2 blockers, 7 majors, 1 minor, 3
  uncertain. The minor is not described here: its round output was not
  among those read when this record was completed, and it is left
  undescribed rather than guessed. Blockers: the Windows control pipe could lose the binding
  between the caller's identity and the connection (fixed: one
  driver-owned prefix-and-caller transition per connection generation);
  the Windows dump gate was narrower than ADR 0004 O25, point 2 (fixed:
  both classes of process, and a positive control for the dump test).
  Majors: Windows DNS cancellation state; DNS answers reported complete
  too early; descriptor adoption before the ancillary header was checked;
  the overlapped pipe API's lifetimes and secrets; the ABI and inventory
  checks; unnamed caps; the per-sink logging cap. All fixed. The
  uncertain items were deferred to the release gates the ADR names.
- **Round 2, verification:** FAIL. Three majors not resolved (DNS
  cancellation, DNS completeness, the macOS logging cap) and one new
  blocker (an oversize audit event could be counted as delivered). All
  fixed.
- **Round 3, verification:** FAIL, 2 new majors (a second
  `DnsCancelQuery`; a partly rejected Windows answer classed as
  complete). Fixed.
- **Round 4:** the control IPC design's verification required sheet 18's
  prefix-and-caller transition to handle short reads and results after
  close (1 major). Fixed.
- **Round 5, the cryptography decision's diff** (`mem-wipe`, row 24):
  FAIL, 2 majors (the wipe rested on a fence that does not guarantee
  ordering; the release check could be skipped). Fixed: the contract
  rests on volatile writes; a release-assembly check with a failing
  control is the site's gate.
- **Round 6, a check across several documents:** one blocker applied
  here (the wipe's caller list lacked the installation-key path). Fixed.

## Rounds 7 to 14 (GPT `gpt-6.2-astra` and GLM `glm-5.3`)

- **Round 7 (GPT, the whole ADR):** FAIL, 1 blocker, 8 majors, 1 minor.
  - Blocker: the privileged mount step sent the FUSE descriptor without
    checking its recipient. Fixed: it checks the peer's uid on the same
    stream before sending (sheet 14), with a refusal test.
  - Majors, all fixed: the pid-reuse case of sheet 20 was not exercised;
    the wipe's in-crate owners were not named; the Windows DNS reader's
    precondition was not stated; the macOS settle test could pass without
    its timing; oversize gap events could exceed the smallest sink;
    prototype mismatches could pass the ABI check; the inventory could
    not represent staged rows; the inventory did not check each block's
    operation.
  - Minor: the IPv6 bind could not carry a scope id. Fixed: unscoped
    addresses only.
- **Round 8 (GPT, verification):** FAIL, 5 majors, 1 minor; four came
  from round 7's own edits (sheet 20's setup against its evidence, the
  wipe's injection rule, the inventory's opening rule, the timing credit
  rules). The fifth major: the Windows DNS reader's pre-code check named
  readable storage only for a header reached through the next-record
  link, not for the first header or the selected SRV or MX fields, and
  relied on a reported length. The minor: the macOS gate said a missed
  quiet interval exercised "neither case", though only the second case
  needs it. All fixed.
- **Round 9 (GPT, verification):** FAIL, 2 majors (sheet 20 must show why
  a refusal closes the gap; the macOS second case had to rule out the
  higher-priority record). Fixed.
- **Round 10 (GPT, verification):** PASS.
- **Round 11 (GLM, security, the whole normative text):** PASS, no
  blocker; 1 major, 3 minors.
  - Major: the macOS DNS settle rule could return an SRV set missing its
    higher-priority record, and its own gate could never pass. Fixed:
    the settle completes nothing; macOS DNS returns no record set until
    a completeness signal is qualified, and discovery there uses explicit
    configuration (fail closed).
  - Minors, fixed: sheet 13's length check had no test; point 1.1's
    build-script and non-Rust clauses are review-enforced (now stated);
    the unified-logging concurrency claim is UNVERIFIED and gated.
- **Round 12 (both, the diff):** GLM PASS. GPT FAIL, 2 majors, 3 minors:
  a sole "." SRV target and the AFSDB prerequisite; AFSDB completing at
  the settle; the delayed-SRV oracle; build scripts in other crates; a
  sanitizer pass standing in for documentation. Fixed.
- **Round 13 (both, the diff):** GLM PASS. GPT FAIL, 1 major (a sole "."
  could be returned before a second record arrives) and 3 minors (the
  collector decoding targets, the mixed-type test, editing a build
  script). Fixed: nothing completes at the settle.
- **Round 14 (both, the diff):** GLM PASS. GPT 3 minors, fixed and
  recorded; the rounds stopped under the stop rule
  ([docs/workflow.md](../workflow.md)):
  - the macOS collector test still expected "unusable answer" for a
    rejection only the shared decoder detects, though held records are
    now discarded at the deadline (a test oracle);
  - the test of a sole "." mixed with another SRV record, the case
    behind the original timing finding, had been deleted (a test
    oracle);
  - a release-gate sentence still said the tests could show the rule
    gives whole record sets, though no record set is returned until a
    completeness signal is qualified (the gate sentence).

No finding was refuted. No owner decision was changed by a fix.
