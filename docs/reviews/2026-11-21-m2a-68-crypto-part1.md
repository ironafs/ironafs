# Review record: `ironafs-crypto`, the random source (part one)

## The change

Class S. Issue #68 (plan id M2a-53), its first pull request of two.

- A new pure crate, `crates/ironafs-crypto` (`no_std` with `alloc`; one
  dependency, the pure workspace crate `ironafs-time`; no third-party
  dependency): the interface through which protocol crates reach
  cryptography (ADR 0004, C5, point 1). It holds the cryptographic random
  source only.
- `EntropySource`: a source that fills all of the buffer or fails, supplied
  when the client is composed; in production the operating system's own
  source, through the safe `ironafs-os` sites of ADR 0005.
- `CryptoRng`: the production `Rng` of `ironafs-time` (C4, point 7), built
  only from an `EntropySource`. `CryptoRng::start` draws a 16-byte probe
  and discards it, and refuses the start with the source's error and code
  if the probe fails. `fill` passes a failure on as an `RngError`: no
  fallback source. A `compile_fail` doc-test shows that a type that
  implements `Rng` alone, as a seeded generator does, cannot be passed to
  `start`.
- `EntropyError`: unavailable or filtered, failed (each with the operating
  system's code), and a bad byte count.
- Not in this change (part two, after the `ironafs-os` random sites,
  #101): the production source's wiring at composition, and the startup
  and refusal tests: a missing and a filtered system call refusing startup
  with the errno in the report, and a planted blocking fill holding
  `READY=1` until it completes and failing at the start timeout. Part two
  also adds `cargo nextest run -p ironafs-os` and the composing crate's
  tests, and clippy on `ironafs-os` for the Linux, macOS and Windows
  targets.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## Findings

GPT, round 1:

- **Minor (origin: GPT round 1; kind: test coverage), fixed
  (`7a0875f`):** the startup probe test counted calls only, and its fake
  also succeeded on an empty slice, so a zero-byte probe would have
  passed. ADR 0005's adapters make no call for an empty buffer, so such a
  probe would check nothing. The fake now records the bytes requested,
  and the test asserts one request of 16 bytes. A probe length of 0 was
  planted and the test failed.
- **Minor (origin: GPT round 1; kind: test over-specifies the contract),
  fixed (`7a0875f`):** the partial-write test asserted what the buffer
  held after `Err`, which the `Rng` contract leaves unspecified. The fake
  now counts failures that wrote part of the buffer, and the test asserts
  that path ran and that `fill` returned `RngError`. The contract is
  unchanged, consistent with `ironafs-time`'s `Rng` documentation.
- **Minor (origin: GPT round 1; kind: documentation overstates), fixed
  (`7a0875f`):** the constructor documentation implied the trait bound
  keeps every non-OS generator out. It now says a type that implements
  `Rng` alone cannot be passed to `start`, that any `EntropySource`
  satisfies the bound, so the composition chooses the provider, and that
  the probe is an availability check for a trusted provider, not a test
  of the bytes.
- **Minor (origin: GPT round 1; kind: documentation against ADR 0005),
  fixed (`7a0875f`):** the `EntropyError` documentation listed a macOS
  `errno` beside the `SecRandomCopyBytes` status, though ADR 0005 selects
  only the latter, and did not say which path keeps the code. It now
  names the code of each selected source (`getrandom`'s `errno`,
  `SecRandomCopyBytes`'s non-zero status, `BCryptGenRandom`'s `NTSTATUS`),
  says `CryptoRng::start` returns the provider's error unchanged, and
  says a later failed fill returns an `RngError` without a code.

Both seats also recorded these as uncertain, not as findings:

- Neither could build or run the tests in its read-only sandbox; GPT
  type-checked the library against `core` and `alloc` on the six
  configured targets in both profiles, compiled both doc-test snippets
  directly, and ran `check-deps`, the format check and the 11 existing
  tests.
- Neither had issue #68's full text; both judged the change against the
  brief's description of part one.
- GLM: an operation-time failure loses the operating system's code,
  because `RngError` is opaque by design in `ironafs-time`; only the
  startup refusal carries it. The documentation now says so.
- GLM: a future test-only crate could implement `EntropySource` over a
  seeded generator. `check-deps` keeps test-only crates out of shipped
  ones; part two's wiring must keep the operating system's source as the
  only provider.
