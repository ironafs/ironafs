# Review record: the fuzz crate, its pinned tooling and the XDR decode target

## The change

Class I. Issue #45 (plan id M2a-12). It lands in one pull request with
M2a-14, whose decoder its one target runs.

- `fuzz/`: the top-level fuzz crate, excluded from the workspace, with its
  own lock file, lints, clippy, fmt and `cargo deny` runs, and a nightly
  pinned by date for `fuzz/` only (`nightly-2026-11-01`). Its manifest
  also has an empty `[workspace]` table. Cargo keeps searching parent
  directories past an `exclude`, so without it a checkout nested inside
  another workspace would claim the crate.
- One target, `ironafs-xdr_decode`. It decodes arbitrary bytes as each test
  type of `docs/specs/xdr.md`, section 10, and asserts the properties of
  10.4. The test types come from the integration tests' own file.
- `fuzz/deny.toml`: the root policy with two named entries changed. One is
  an NCSA licence exception for `libfuzzer-sys` 0.4.13 alone. The other
  allowlists by name and version the three build scripts the lock file's
  metadata shows.
- `cargo xtask check-fuzz-deny`: fails when `fuzz/deny.toml` differs from
  the root file by more than those entries, or when the root names NCSA.
- `cargo xtask fuzz`: replays every target's tracked seeds once, and passes
  only when the engine reports running every seed. A failure is reported
  by target and the failing seed's git object id. The engine's output,
  which can hold the input, is never shown.
- Each new command has a `--self-test`. CI's lint job runs the policy
  check, both self-tests and `cargo deny` in `fuzz/`. A `fuzz` job on x64
  and Arm64 Ubuntu runs fmt and clippy in `fuzz/` and replays the seeds.
  `ci-ok` requires it.
- Not in this change: the time-bounded fuzzing job and reproducer
  encryption (M2a-84), and the issue's test-strategy additions, which move
  to M2a-88 because M2a-76 is not accepted.
- The dependency itself (`libfuzzer-sys`) is the owner's decision, taken
  at the pull request. This review covers the change, not that decision.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## The dependency decision

The owner approved `libfuzzer-sys` `=0.4.13` (2026-11-21), under the
existing exception in `fuzz/deny.toml`: NCSA for that exact version of
that crate, in the fuzz crate's policy only, never the root's. It is an
exception, not a `clarify` entry: the licence the crate declares is kept
as it stands. Since this lands before 2026-11-27, `fuzz/Cargo.lock` holds
`cc` at 1.11.2 (`cargo update --manifest-path fuzz/Cargo.toml -p cc
--precise 1.11.2`); the root lock file is not changed.

- **Native sources.** The crate declares `(MIT OR Apache-2.0) AND NCSA`.
  Its bundled LLVM libFuzzer files carry `Apache-2.0 WITH LLVM-exception`
  in their own headers (55 files under `libfuzzer/`, none without it),
  which the policy allows. The exception covers the NCSA the crate
  declares.
- **Cost.** Ten third-party packages in `fuzz/Cargo.lock`: `libfuzzer-sys`
  and nine transitive (`arbitrary`, `cc`, `find-msvc-tools`, `jobserver`,
  `libc`, `shlex`, and `getrandom` with its `cfg-if` and `r-efi`, which
  the lock file holds through `jobserver` on Windows only). None of them
  reaches the workspace's lock file.
