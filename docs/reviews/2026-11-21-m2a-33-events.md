# Review record: `ironafs-events`, part 1

## The change

Class S. Part of issue #94 (plan id M2a-33).

- A new pure crate, `crates/ironafs-events` (`no_std` with `alloc`, no
  dependencies, no features, no build script), and its specification,
  `docs/specs/events.md` (protocol, class S, draft):
  - the event catalogue: definitions only the crate can build, a
    diagnostic and an audit stream, static fields limited to catalogue
    choices, at most one server text field per event;
  - field values through a sealed trait, so a secret type cannot be a
    field (two `compile_fail` doc-tests), and `write_redacted` for secret
    types' formatting;
  - server text kept to 256 bytes and written only escaped;
  - redaction by data class and policy;
  - producer-role and direct-audit checks;
  - a per-subsystem rate limiter that takes the instant as an argument,
    with every refusal counted, and loss counters;
  - counters, fixed-bucket histograms and health;
  - the journald native-protocol and RFC 5424 encoders, each measuring a
    message before allocating it, fitting it to its cap (16 KiB, 480
    octets), marking truncation, and refusing an event whose identity and
    required fields alone do not fit.
- Not in this change: the `cargo xtask events` generator, the sink
  transport in `ironafs-os` with its cap-equality test, the fuzz target,
  and read-back through journald and a syslog receiver.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first; each fix shown failing before it was made).

## Findings

Each finding is quoted as the reviewer wrote it, then its disposition.

GPT, round 1:

- "major crates/ironafs-events/src/event.rs:124 | The public builder
  accepts any static EventDef. Its role check trusts the supplied
  definition, while catalogue tests validate only entries in ALL. The
  encoders also trust the definition's names and data classes."
  **Fixed (`017ce9e`).** `EventDef` and `FieldSpec` have crate-private
  fields read through getters; no other crate can build one. A
  `compile_fail,E0451` doc-test shows a forged audit definition refused;
  it compiled before the fix. Specification 5.1, point 9.
- "major crates/ironafs-events/src/field.rs:190 | The sealed trait blocks
  new external implementations and generic formatting into a field. It
  does not establish the provenance of accepted values. ServerText
  accepts arbitrary bytes, Reference accepts any 32-byte array, and
  &'static str can hold runtime data. Escaping preserves the information
  in the retained bytes."
  **Fixed for static text (`017ce9e`); refuted for `ServerText` and
  `Reference`, refutation accepted in round 2.** Each static field has a
  closed list of choices in the catalogue; any other string is refused
  (`EventError::ValueNotAllowed`) and the event keeps the catalogue's own
  string. A crate with no dependencies (ADR 0004, O1, point 1) cannot
  learn where bytes it is given came from, and server text must accept
  arbitrary bytes; ADR 0004, O5, point 3, requires that server text never
  be placed in a payload as it arrived, which escaping meets. The
  specification (5.2, point 6) states the limit for integers, server text
  and references alike.
- "major crates/ironafs-events/src/fit.rs:83 | Fitting allocates the
  complete rendered message and encoded buffer before comparing the length
  with the cap. Even canonical definitions accept unrestricted &'static
  str values. AUDIT_GAP.kind accepts any such string, although its
  documented domain has three values."
  **Fixed (`017ce9e`).** Rendering writes into a sink; each candidate is
  measured into a counter that keeps no bytes, and the one output buffer
  is allocated at its exact size after it is known to fit. Static values
  come only from the choices; `audit.gap`'s `kind` takes its three values.
- "major crates/ironafs-events/src/syslog.rs:211 | The RFC 5424 header and
  NILVALUE structured-data field are framed before the message. Within
  MSG, unquoted server text precedes the IronAFS key-value suffix and can
  contain the same delimiter and key syntax. The property at
  tests/it/syslog.rs:177 searches the entire MSG for its truncation flag."
  **Fixed (`017ce9e`, `6f137cb`).** `MSG` is now only `key=value` pairs:
  IronAFS's keys first, the quoted message last. Every value that can hold
  server text is quoted, and escaping leaves no bare `"` or `\`. A strict
  test reader rejects server text imitating the pairs, and the property
  now reads the pairs instead of searching the text. Specification 5.9,
  point 6.
- "minor crates/ironafs-events/src/fit.rs:109 | The bisection assumes
  candidate size grows with the common text limit. With multiple
  server-text fields, a short field can become complete and shed its
  marker while a longer field remains cut. The encoded size can decrease
  as the limit increases."
  **Fixed (`017ce9e`).** A catalogue rule and test: an event has at most
  one server text field, so the size is monotone below the whole length.
- "minor crates/ironafs-events/src/limit.rs:121 | Flooring the nanosecond
  interval makes some configured rates slightly permissive. At 999,999
  events per second the limiter uses a 1,000 ns interval, which permits a
  sustained 1,000,000 per second. The overflow test uses burst 1 and
  exercises only the virtual-arrival addition. The property generates
  only increasing timestamps."
  **Fixed in part (`017ce9e`), completed (`6c6f028`).** The interval
  rounds up, with a test of the reported rate. Round 2 found the overflow
  tests both reached `now + tau`; `6c6f028` adds a test of the
  arrival-time overflow (burst 1), shown to fail on a planted saturating
  addition, and the property now also moves time backwards.
- "minor crates/ironafs-events/src/event.rs:93 | Derived Debug for
  EventBuilder and Event prints stored values before applying redaction.
  Routine encoder policy is applied only in render.rs."
  **Fixed (`017ce9e`).** `Debug` shows the event's name, the direct flag
  and the names of the fields set, never a value.
- "minor docs/specs/events.md:515 | The invariants table presents
  refused-record accounting as covered. The tests prove limiter
  suppression counts and explicit LossCounters recording. Builder
  refusals, encoder outcomes, and the delivery of drained summaries have
  no automatic accounting in this crate."
  **Fixed (`017ce9e`).** The table row says what this crate counts and
  what the callers own.
- "minor crates/ironafs-events/tests/it/server_text.rs:24 | The newline
  test checks escaped content and selected journal fields. An escaping
  pass-through can fail the content assertion while push_field still
  safely frames the newline in its binary form."
  **Fixed (`017ce9e`).** The test requires every journald field to take
  the simple form.

  **Fixed (`017ce9e`).** The claim is removed; a leading `=` in a journald
