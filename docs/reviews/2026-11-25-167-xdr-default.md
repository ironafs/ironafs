# XDR default-arm fixture specification (#167)

Class S specification change. [XDR section 10](../specs/xdr.md#10-tests)
now defines a fixture with a closed discriminant and a default arm.
It gives #165 a fixture whose explicit and default arms have the same
wire length. The decoder rule in section 5.4 point 7 is unchanged.

## Review

Base `cd5aef93989f79e216eddedaf8816772c92d4240`. Reviewed specification
SHA-256 `846928c0c71373375309477e3b0605f82d46e105fb691a73ca2f84298c08352d`.

| Seat | Served model and effort | Verdict |
|---|---|---|
| Design | `glm:glm-5.4` (high) | PASS, no findings |
| Independent design | `gemini:gemini-4-carbon-high` (high, uncalibrated on IronAFS) | PASS, no findings |

The controller confirmed both verdicts completed with the original
markers and that the spec and patch digests still matched. Quota
headroom was not reported. The two valid cases select PALE's explicit
arm and VIVID's default arm. R9b uses an undeclared value of the same
enum and a complete payload, so the test distinguishes discriminant
validation from arm selection. The existing R8 and R9a cover different
conditions.

## Evidence

- INSPECTED [RFC 4506, sections 4.3, 4.5 and 4.15](https://www.rfc-editor.org/rfc/rfc4506.html#section-4.3)
  and the profile's validate-before-dispatch rule. The decoder records
  the first enum word's offset before reading it, and the non-secret
  error carries that offset.
- EXECUTED an independent big-endian `u32` and `u64` byte calculation
  for G14, G15 and R9b. The three byte strings matched the spec and
  all were 12 bytes. This establishes wire layout, not decoder behavior.
- EXECUTED `cargo xtask check` on macOS with the reviewed spec at base
  `cd5aef9`. All 995 existing workspace tests passed.
- PROPOSED under #59, Class I: add the concrete vectors, round-trip
  cases, reject assertion and three tracked fuzz seeds. Run the fixture
  tests and Linux seed replay, and aim the reject assertion at a
  planted default-before-validation decoder once to prove it can fail.
