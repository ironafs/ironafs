# Review record: `ironafs-os`, Linux part, parts B and C

## The change

Class S. Issue #57 (plan id M2a-09), parts B and C of five, on top of
part A. Part of #57.

- **Part B, the dump controls (ADR 0005, sheets 11, 12 and 24):**
  - `unix-nodump` (row 11, Linux part): `disable_dumps`, which sets the
    core-file limit to zero, makes the process non-dumpable and reads the
    attribute back; every variadic `prctl` argument is a `c_ulong`;
  - `linux-dontdump` (row 12): `SecretBuffer`, a 64 KiB block that is
    also 64 KiB aligned, excluded with `MADV_DONTDUMP` and wiped on drop.
    A failed exclusion hands out no buffer;
  - `cargo xtask check-wipe`, mem-wipe's release-assembly gate (sheet 24);
  - the marker tests of ADR 0004, O26, point 5, with their positive
    control, for core files and for a piped collector.
- **Part C, the local socket sites (sheets 13 and 14):**
  - `linux-peercred` (row 13): `peer_credentials(&UnixStream)`. It first
    asks the standard library for the peer's address, then reads
    `SO_PEERCRED`. It refuses any length but 12 and ids of -1;
  - `linux-fdpass` (row 14): `send_fd` and `receive_fd`, one descriptor
    beside one data byte, with `MSG_NOSIGNAL` and `MSG_CMSG_CLOEXEC`,
    `EINTR` retried. `fdpass::accept` checks the control length, the
    header's length, level and type, adopts every descriptor a valid
    `SCM_RIGHTS` message delivered, and only then refuses for anything
    else;
  - `struct msghdr` and `struct cmsghdr` declared per C library
    (`abi/gnu.rs`, `abi/musl.rs`; point 5.2).
- **Checks:**
  - `check-os` lets a row's `abi.rs` choose its C library's declaration
    file by `target_env`, and refuses any site in those files;
  - `check-abi` gains `defines` (only `_GNU_SOURCE`, for `struct ucred`)
    and `expressions`, so a constant is compared with a C expression such
    as `CMSG_LEN(sizeof(int))`.
- **Tests:**
  - every site's failure paths are driven through its public wrapper
    under Miri, with stand-ins that plan each answer and its errno;
  - kernel tests count `/proc/self/fd` for each descriptor case.
- **CI:**
  - the os-linux lanes prove the four new sites per target and lint
    `ironafs-os` per target;
  - the marker tests run as the runner's user, the root cases in their
    own step, each case required by name;
  - the Miri job names the new wrapper tests.
- **Written by** `claude-code:claude-opus-5-5` (Claude Code subagents,
  test first).

## Open items

- **O1 (G1, major), waiting on the owner's decision on the amendment
  below.** GPT, round 2: "G1 — NOT FIXED. On a genuine Unix stream, the receiving socket must have SO_PASSPIDFD enabled, and the scoped code has no path that enables it. Linux can inherit the option from a listener. If the receive delivers SCM_RIGHTS, that message consumes all 24 control bytes and prevents pidfd installation. The precise condition is that the receive delivers no SCM_RIGHTS and leaves room for SCM_PIDFD. A sender may have supplied rights that the kernel did not deliver. The one-byte condition applies to genuine streams. A datagram wrapped as UnixStream can return ancillary data with zero payload bytes." The exposure is
  recorded in `fdpass`'s documentation. No site of ADR 0005 sets
  `SO_PASSPIDFD`.
- **O2 (G5, major), waiting on the same decision.** GPT, round 2: "G5 — PARTLY FIXED. The listener regression test and user-namespace documentation are present. The address check establishes a connected Unix peer but does not establish SOCK_STREAM. Linux initializes cached credentials for a datagram socket pair and can change the connected datagram peer without replacing those credentials. The checks for a peer address and IDs other than −1 both pass in that case." The exposure is recorded
  in `linux_peercred`'s documentation.
- **O3 (G10, minor), recorded departure.** GPT, round 2: "G10 — PARTLY FIXED. Received is no longer Copy or Clone in production and the by-value handoff has no intervening fallible operation. The documented departure still crosses a function boundary that ADR 0005 sheet 14, line 709, explicitly constrains."
  - A received descriptor is an integer from the receive's read of its
    control buffer until `accept` adopts it. That span is two functions,
    with no fallible step or early return between them.
  - The split is kept so that the checks stay a safe function over owned
    values, for the tests and the planned fuzz target. The amendment
    below would record it.

Proposed amendment, **not applied**, for the owner (ADR 0005 point 7.1):

> **Amendment proposal: ADR 0005, rows 13 and 14 (Working; point 7.2), with sheets 13 and 14.**
>
> *Why.* Review of #57 parts B and C (GPT, two rounds) found two exposures that safe Rust cannot close and the closed list does not yet allow closing:
> - **Row 13, the socket type.** `peer_credentials` takes a `UnixStream`, but safe Rust can wrap any descriptor as one. The wrapper now refuses a socket with no connected peer (the standard library's `getpeername`) and ids of -1. That still lets through a datagram socket of a pair that has been connected to another peer, whose `SO_PEERCRED` answers the pair's original credentials.
> - **Row 14, the pidfd.** A receiving socket with `SO_PASSPIDFD` set (directly, or inherited from the listener it was accepted from) gets an `SCM_PIDFD` control message, and the kernel installs the pidfd in the receiver. It does so whenever the receive delivers no `SCM_RIGHTS` message and leaves room for it. Sheet 14's checks refuse that message without adopting its integer, so the pidfd leaks. No IronAFS site sets the option; a socket unit's `PassPIDFD=` or foreign code can.
>
> *Row 13 becomes:* `int getsockopt(int, int, int, void *, socklen_t *)` with `SOL_SOCKET` and `SO_TYPE` (into an `int`), then `SOL_SOCKET` and `SO_PEERCRED` (into a `struct ucred`), only, on a borrowed `UnixStream`. The block column becomes "two (one per option)".
>
> *Sheet 13, obligations, added:*
> - Before the credential read, the socket's type is read into a zero-initialised local `int`, with a local length set to `sizeof(int)`, both passed by exclusive pointer for the call.
> - A non-zero return, a returned length other than `sizeof(int)`, or a type other than `SOCK_STREAM` is an error: "not a Unix stream".
> - The peer-address check (`getpeername` through the standard library) and the refusal of ids of -1 stay. Together they refuse a listener, an unconnected socket, another family, and a datagram socket, a pair's included.
> - Safety: the same as the credential read's, for one `int`. The kernel writes at most `*optlen` bytes and the length.
> - *Test:* a reconnected datagram socket of a pair, wrapped as a stream, is refused. The stand-in returns a wrong type, a short length and an over-long length.
>
> *Row 14 adds* the constant `SCM_PIDFD` to the control types the receive recognises. There is no new foreign item, block or flag: the adoption block already exists.
>
> *Sheet 14, obligations, changed:* "Only a header that passes all of these holds descriptors" gains a second descriptor-carrying type.
> - A header of level `SOL_SOCKET`, type `SCM_PIDFD` and length exactly `CMSG_LEN(sizeof(int))`, within the returned control length, holds one descriptor: a pidfd the kernel installed.
> - It is adopted as an `OwnedFd` like a delivered descriptor, then refused (a new error, "the peer's pidfd arrived instead of a descriptor"), which closes it.
> - An integer from any other control message is still never adopted or closed.
> - With an `SCM_RIGHTS` message in the buffer, the kernel creates no pidfd (it sets `MSG_CTRUNC`), and the existing rule holds.
> - The raw-descriptor span becomes "between the checked read of the control buffer and its adoption: the receive and the checks it hands what it read to by value, with no fallible step or early return between".
> - Safety, for the adoption: the kernel installed the pidfd in this process for this receive (`scm_pidfd_recv`: `fd_install` after `put_cmsg` succeeded), and no other code has seen it. So the `OwnedFd` is its only owner, as for `SCM_RIGHTS`.
> - *Test:* the checks over an `SCM_PIDFD` header, through the production adoption, close its descriptor (count in `/proc/self/fd`). A planted `SO_PASSPIDFD` would need a `setsockopt` site, which this amendment does not add, so the end-to-end case is MISSING until a site or the daemon's composition sets it.
>
> *Constants and their sources:*
> - `SO_TYPE` = 3: musl `<sys/socket.h>`; Linux `<asm-generic/socket.h>`, which glibc's headers include.
> - `SOCK_STREAM` = 1: glibc `<bits/socket_type.h>`; musl `<sys/socket.h>`.
> - `SCM_PIDFD` = 4: glibc 2.39 and later, `<bits/socket.h>`, only under `__USE_GNU` (so row 14 gains `defines: ["_GNU_SOURCE"]`); the Linux kernel's `include/linux/socket.h` (since 6.5), which is not in the installed user-space headers; not in musl 1.2.5 (Debian 13's `musl-dev`, checked).
>
> *ABI check rows:*
> - **glibc** (x86_64 and aarch64): `SO_TYPE == 3`, `SOCK_STREAM == 1` and `SCM_PIDFD == 4` by name, with `_GNU_SOURCE`.
> - **musl:** `SO_TYPE` and `SOCK_STREAM` by name. `SCM_PIDFD` is a kernel value that musl's headers do not name, and no header installed on a musl system names it. The proposal is that `check-abi` on a musl target skips only the constants a row lists as `kernel_only`, and only where the C library's headers lack them. The value is then proved by the glibc lane of the same architecture, which `ci-ok` requires. A `check-abi` self-test plants a `kernel_only` constant that is wrong on glibc, which must fail there.
> - A literal `expressions` mapping ("4") is rejected: it would prove nothing.
>
> *Unchanged:* no new foreign function, library, target or site. Rows 13 and 14 stay `unsafe fn`, from the C library.
