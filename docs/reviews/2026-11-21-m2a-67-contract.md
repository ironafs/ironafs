# Review record: the contract between the core and the layers

## The change

Class S. Issue #67 (plan id M2a-21), the specification part; the crate's
code is its own pull request.

- `docs/specs/vfs-contract.md`: the specification of ADR 0004 C7's
  contract. It covers:
  - the caller, handle and binding operations with their payloads, and
    caps on every value a layer supplies;
  - capabilities and the core's record check;
  - the request table, its single-writer claim, the completion owner,
    cancellation and deadlines, answering the seams specification's Q3;
  - the fence check at submission: lock sets, registration before the
    check, the drain;
  - the invalidation stream's acknowledgement and failure-report rules;
  - the rule that only the composition names `Mint`, and its check;
  - the error mapping per operating system, with seven added values.
- `docs/specs/README.md`: the page's index row and register rows E61 to
  E66 (errno(3) and fuse(4) from Linux man-pages 6.19, the kernel's FUSE
  documentation, the macOS 27.2 SDK headers, MS-ERREF 2.3 and 2.3.1,
  MS-SMB2 2.2.30).
- **Written by** `claude-code:claude-opus-5-5` (drafting, and the fixes
  of both rounds).
- The branch is stacked on #113 (`m2a-71-seams`, at `9fa32da`), whose
  specification hands this page the request table, the completion owner,
  the submission check, the reply-over-cap mapping and the deadline's
  clock.

## Findings

Origin tags: **[draft]** pre-existing in `7e1ddc6`; **[fix 1]** introduced
by fix round 1.

### Round 1, Gemini (all fixed in `ba8517d`)

- **G1, blocker [draft]: a claim after the deadline wrote nothing.** A
  worker whose claim failed after the deadline wrote nothing, and the
  timer then found the entry claimed and wrote nothing either. Now the
  winner of the compare-and-set, and only the winner, writes the
  completion it claimed with. A claim after the deadline, by any party,
  carries the deadline's error (5.8, point 4; 5.9, point 2).
- **G2, blocker [draft]: one lock for multi-node replies, and gaps in the
  fence.** Four parts, all fixed:
  - each operation has a lock set, taken in object-key order (5.9,
    point 1);
  - a submission takes its sequence number before its check, under a
    sequentially consistent order with the recorders (5.9, points 2
    and 3);
  - gates are set when a change is recorded (5.9, point 3);
  - a drain that reaches the event's deadline is a purge failure (5.9,
    point 4).
- **G3, major [draft]: commit at its deadline.** A commit at its deadline
  could complete with `TimedOut` against C9, point 5, and `volume_sync`
  had no deadline. The deadline's error is now `NotYetStored` while a
  store is in progress, and `volume_sync` has an entry and a deadline
  (5.8, points 3 and 4).
- **G4, major [draft]: errors the layers need.** Seven values were added
  under C46, point 1's "include": `NotADirectory`, `IsADirectory`,
  `NotEmpty`, `NoAttribute`, `TooSmall`, `PastEnd`, `Protocol` (5.12,
  point 9). Extended attributes are never truncated (5.4, point 5).
  Values from the server that the contract cannot carry, and replies over
  their cap, are `Protocol`, never `OutOfRange` (5.12, points 5 and 7).
- **G5, major [draft]: uncapped inputs.** New caps cover subscriptions,
  locks, truncate size, both copy-range ranges, extended-attribute
  writes, the named-stream selector, the `control` reply and undefined
  bits. The reserved operations now have signatures, and `control`
  carries its node (5.2, 5.4, 5.5, 6).
- **G6, major [draft]: the acknowledgement protocol.** Fixed by:
  - one revision counter per binding, with each effect's merge revision
    (5.10, point 1);
  - `PurgeFailed` with node and overflow-node forms (5.10, point 5);
  - one validity rule for acknowledgements and failure reports (5.10,
    point 6).
- **G7, minor [draft]: request ids and teardown.** An id is freed at its
  claim, and teardown waits for claimed writes. Every wait after a
  mutation is sent takes only the shutdown cancel. A duplicate id is
  dropped with no completion (5.2, point 1; 5.8, points 1, 7, 9).
- **G8, minor [draft]: the `Mint` scan's alias gaps.** The check now bans
  the token itself and also uses clippy's type ban, with a canary for
  each route; `Mint` has no `Default`, `Clone` or `Copy` (5.11). C13,
  point 2's partial list is raised in Q7.
- **G9, minor [draft]: capabilities on binding operations.** Binding
  operations carry no capability to act with; `release` and
  `release_directory` take the handle they end, by value. `open` no
  longer lists a second extension list.

### Round 1, GLM (all fixed in `ba8517d`)

- **L1, major [draft]: `purge_failed` unvalidated.** A layer could revoke
  handles in every binding with forged reports. Fixed with G6's validity
  rule, a security-table row and acceptance case 9.
- **L2, minor [draft]: three rules for a duplicate acknowledgement.** Now
  one (5.10, point 6).
- **L3, minor [draft]: a no-replace rename had two errors.** The contract
  value is `NotSupported` (N46, point 1); the POSIX layers present it as
  `EINVAL` (C10, point 6) through a per-operation row (5.6, point 9;
  5.12, point 2).
- **L4, minor [draft]: a failed seek had no error.** `PastEnd`, presented
  as `ENXIO`.
- **L5, minor [draft]: truncate size, the access mask and the filter
  uncapped.** Capped, and the reject corpus extended (5.2, point 8;
  10.3).
- **L6, minor [draft]: wrong decision-to-section pointers.** Corrected,
  and a C10 row added.
- **L7, minor [draft]: the `Mint` check failed on itself.** Its own
  module and canary are now exempt, and the macro-fragment limit is
  stated.
- **L8, minor [draft]: the drain's expiry.** Fixed as G2's fourth part.

### Round 2, Gemini (fixed in `5ba3297`)

- **Minor [fix 1]: report validity.** The validity rule treated an
  overflow as answered by its first node report, and its repeat and
  fault classes overlapped. Now:
  - an overflow stays open until its acknowledgement;
  - each node may be reported once under it;
  - a slot has at most one delivery unanswered;
  - the two classes are disjoint (5.10, points 1 and 6).
- **Minor [fix 1]: subscription caps.** The cap table gave `Busy` for a
  second subscription on one handle, where point 9 gives `Conflict`; the
  row now names both. `unsubscribe` was said never to fail although it is
  a handle operation; it is now idempotent, with an ordinary completion
  (5.2; 5.5, point 8).
- **Minor [fix 1]: the extended-attribute list and the in-flight mark.**
  The list's length was undefined across systems:
  `list_extended_attributes` now takes no budget and returns every name,
  capped at 65,536 bytes counted as each name plus one, and each layer
  computes its own length and too-small error (5.4, point 5). "Mark it in
  flight" was a separate step that could be missed: the counter's advance
  itself now puts the number in flight (5.9, point 2).

### Round 2, GLM (fixed in `5ba3297`)

- **Minor [fix 1]: the filter's bits.** Point 8 refused undefined bits of
  a filter whose bits the page never defined. The filter is now the four
  effect kinds of 5.10 (5.5, point 7).

### Questions from the scripted core's work, settled in `5ba3297`

1. **Releasing a revoked handle** is ordinary and not a layer fault, since
   a FUSE kernel releases every open. Only a capability with no record
   for the binding is a fault (5.6, point 2).
2. **An attestation the core does not accept** (a uid other than a
   per-user FSKit binding's owner, or an unknown or ended SMB session) is
   refused with `Access`. An unknown session is also a fault. A uid on a
   shared binding always has a context (5.3, point 1).
3. **A late `OverflowNode`** for a node held now but not at the
   overflow's delivery is a repeat once the overflow is acknowledged, and
   a fault while it is open. An honest layer cannot send the second,
   because every reply is fenced while an overflow is open (5.10,
   point 6).
4. **Fault counts are per binding,** confirmed: one counter per binding,
   never charged to another binding or a context (7, point 3).

## Not raised as findings

The seats listed items they could not settle. Each is noted with where it
stands:

- The errno wordings and NTSTATUS values rest on register rows E61, E64
  and E65. The controller read them at source before writing them; the
  planned `errno` and `ntstatus` tests are the standing check.
- GLM: a claimant whose fresh sample precedes the deadline can write
  marginally after it. This is the seams specification's residual, kept
  at decision granularity under the simulator.
- GLM: teardown's wait is bounded by the kernel's acceptance of a reply.
  That is a device-level residual, stated in 5.8, point 9.
- GLM: the seams specification's worked example (its 5.8) shows the claim
  after the lock is released, while this page claims inside the lock set.
  The arbitration is the same. The seams page is not changed here.
- Gemini (round 1): C27, point 4, gives budgets for cache and pins, not
  locks, so the lock cap is this page's. C15, point 6 (Firm), stales a
  failed node "in every binding"; that is kept.

## Decision 29 amendment

After both rounds, the controller settled a question across four
specifications: they listed different values for the cache's fence, this
page asked for sequentially consistent atomics for every value its check
reads, and two texts said "fetch-and-add" for counters that must never
wrap. The callback specification (issue #66) owns the fence tuple and
was amended first; this page now agrees with it. What changed, and why:

- **Section 4, "Ticket".** The ticket is the recorded fence tuple of each
  object the reply carries state of (the callback specification's six
  values, its section 4 and 5.6, points 2 and 3), plus the credential and
  rights generations and the grant (C16, point 3). The "overload record's
  counter" is removed: the callback and Rx specifications replace that
  record with Rx holding what it cannot admit until the suspect epochs
  have advanced, and with the pause generation where Rx cannot hold. A new
  term, "Fence table", names the cache's table.
- **5.9, point 2, step 3.** The check runs the callback specification's
  fence check (5.6, point 2) on each recorded tuple, under the fence
  table's lock, looked up with the request's current context and
  credential generation, and then compares the generations. A reply that
  is never cached is checked on five values, as that specification's 5.6,
  point 3, says.
- **5.9, point 3.** The all-atomics rule becomes a lock-or-atomic rule:
  each value step 3 reads is written under a lock step 3 holds, or is a
  sequentially consistent atomic store read with a sequentially consistent
  load. The fence table's values and the suspect epoch are under the
  table's lock; the pause generation is the one lock-free value. The
  table's lock is a leaf in C39, point 4's order, held only for the check.
  The drain argument gains the step for a value written under a lock. ADR
  0004 (C16, points 1 and 3; C39, point 4) requires visibility before the
  event and a check in the same step as the write, not atomics, so this
  is an `[OWN]` choice made narrower.
- **5.9, point 2, step 1, and section 6, point 4.** "Fetch-and-add"
  becomes a compare-and-swap that rises by 1 and refuses to pass
  `u64::MAX`: a fetch-and-add wraps and cannot refuse.
- **5.9, point 7 (new), and section 13, Q9 (new).** The duty of C16,
  point 6, to push a fence-epoch advance to a binding in its own process
  now covers every change the fence check would see: suspect-epoch
  advances, pause and resume raises, break counter raises and local
  volume epoch changes. Seams' 5.4, point 7, carried part of this duty,
  and it goes with the overload record. This page states the duty only.
  Q9 holds what is open: which task pushes, how bindings are found, and
  coalescing. It blocks out-of-process bindings only.
- **Section 12.** Rows for the callback, Rx and incarnation
  specifications; the seams row no longer cites its 5.4, point 7.

The code this describes is the cache's fence table (issue #91, part 2),
whose last reviews passed. This amendment awaits a scoped review of its
own diff on this branch.
