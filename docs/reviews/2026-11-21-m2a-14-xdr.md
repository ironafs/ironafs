# Review record: `ironafs-xdr`, the XDR codec with caps

## The change

Class S: hostile fileservers send the data this crate decodes. Issue #59
(plan id M2a-14). It implements the XDR profile of `docs/specs/xdr.md`
(issue #42, still on its own branch as this is written).

- A new pure crate, `crates/ironafs-xdr` (`no_std` with `alloc`, no
  dependencies). It decodes and encodes the profile's types as RFC 4506
  sets out.
- **Decoder.** A bounded cursor whose ends are the input's end and the
  tightest enclosing array's limit. Every length and count is checked
  against its declared bound, its cap and both ends before anything is
  reserved. One ledger takes every heap request and holds it to the
  message's memory budget. Each request is reserved once, fallibly, and
  filled by `push` alone. The decoder is strict: non-zero padding, a
  boolean other than 0 or 1, an undeclared enumeration value, a
  discriminant with no arm, and trailing bytes are each rejected. Array
  elements are decoded by a loop. Nesting depth and inline size are
  checked at build time.
- **Encoder.** Two passes. The size pass is checked arithmetic, and it
  refuses whatever the decoder would reject. Then the output is requested
  once and written by `push` alone. `encode_into` never grows, moves or
  frees the caller's allocation. It wipes the buffer before writing, on
  every error and on unwind; that wipe is best effort, and the caller's
  approved wiper is what holds.
- **Secrecy.** Each type states once whether it can hold a secret
  (`Classified`). The encoder checks at build time that a type is secret
  whenever a component it writes is. `encode` refuses a secret-bearing
  message at build time, so such a message goes only through
  `encode_into` and the caller's buffer. A secret-bearing message borrows
  its integers, opaques and strings from the input. Its errors carry no
  offset or length. `Debug` never prints a value or a length.
- **Descriptors.** The entry points `decode`, `decode_traced` and
  `proven` take the cap, the budget and the secrecy from the message's
  type, so a type cannot be decoded under another message's descriptor.
- Tests: golden vectors, round-trip properties over the specification's
  test types, the reject corpus (one fixture per case), the depth limit,
  a small-stack test, the ledger and unwind tests, and compile-fail
  doc-tests. Each compile-fail doc-test stands beside a passing one that
  differs in one line.
- In `crates/xtask`, `check-bans` gained these checks along the way:
  - the crate's own `clippy.toml` must carry every rule 7 ban;
  - every ban in a root configuration must have a planted line;
  - the check refuses to run while `CLIPPY_CONF_DIR` is set;
  - the ban arrays are read in one format only;
  - it refuses a build script that changes what clippy runs with.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first). The round-4 fixes (`40c9877`, `38062dc`, `8a8539f`) were
  written by `claude-code:claude-mythos-5-2`. That was a promotion under
  the workflow's §2 rule. Two completed fix attempts at the standard
  implementer's tier (fix rounds 2 and 3) had failed verification on the
  same defect: how a message's secrecy is classified.

## Findings

Each finding is tagged by origin and kind. Minor findings are grouped.

### Round 1 (fixes in `b359466` and `eceeca8`)

GPT majors, all confirmed:

- **Major, fixed** (origin: pre-existing; kind: correctness).
  `fixed_array` called `T::default()` for every slot after an element
  failed. `Default` makes no promise about allocating or panicking. Fix
  round 1 used a constant placeholder instead. Round 2 then replaced
  that with slots reserved through the ledger.
- **Major, fixed** (origin: pre-existing; kind: contract). `Encoder`
  derived `Debug` over its output buffer, so it could print a secret it
  had already written. It now has its own `Debug`, which shows only the
  message name. GLM found the same defect as a minor.
- **Major, fixed** (origin: pre-existing; kind: contract). `encode`
  accepted a secret-bearing message and returned an ordinary `Vec`. Also,
  `encode_into` cleared a reused buffer without erasing it. Round 1 added
  the wipe. Rounds 2 to 4 brought the build-time refusal and the
  contract that the allocation never moves.
- **Major, fixed** (origin: pre-existing; kind: missing mechanism). The
  decoder had no ledger-backed operation for a structure field or union
  arm held out of line. `Decoder::out_of_line` now checks the minimum
  size against both ends of the cursor, then reserves one slot, then
  decodes into it.
- **Major, fixed** (origin: pre-existing; kind: correctness). The
  fixed-length opaque encoder took a slice of any length, while the
  decoder always read the declared width. The width is now in the type,
  and a compile-fail doc-test shows a wrong width does not build.
- **Major, fixed** (origin: pre-existing; kind: correctness). `proven`
  and the ratio helpers saturated instead of failing on overflow. A
  worst case that overflowed then matched a budget of `u64::MAX`. The
  ratios are now `Option<u64>`, and the arithmetic is checked.

Minors (GPT 4, GLM 2; all fixed):

- the array limit was computed in `usize`, which fails on 32-bit targets
  (now 64-bit throughout);
- the nested-array tests did not tell the parent's tighter limit from
  the child's;
- an encoder test stopped before it reached the check it named;
- the slice `to_vec` call was missing from the crate's allocation bans.
  This was found by both seats. Clippy cannot name `Vec::from` by path,
  so that conversion is left to review and named in the file.

### Round 2 (fixes in `f869dd3`)

- **Major, fixed** (origin: fix round 1; kind: contract). GPT. The
  `Plain` marker that let `encode` take a message was never tied to the
  descriptor's secrecy. GLM found the same as a minor. `Plain` was
  removed, and `encode` now refuses a secret-bearing message type at
  build time.
- **Major, fixed** (origin: fix round 1; kind: contract). GPT. The
  zeroing stores carry no guarantee that the compiler keeps them, and the
  test checked only length, pointer and capacity. The zeroing is now
  documented as best effort, with the caller's approved wiper (ADR 0005)
  as what holds. For a secret-bearing message, `encode_into` refuses an
  allocated buffer that is too small, so a secret is never moved. One part departs from the direction
  given: a buffer with no allocation is still sized once. The spec
  allows that.
- **Major, fixed** (origin: fix round 1; kind: correctness). GPT. The
  constant placeholder still needed a value for every element type, and
  a boxed fixed-length opaque has none. Fixed-length arrays now decode
  into slots reserved through the ledger and move into the array. This
  changed the array's heap ratios in the specification (amended on
  #42's branch).
- Minors (GPT 2, both fixed): the encoder's `Debug` still showed how
  many bytes were left to write; and the boxing helper refused a buffer
  whose reservation gave spare capacity. The second fix was reversed in
  round 3: see below.

### Round 3 (fixes in `f1ddede`, `dcd6b48`, `a719012`, `3dad57e`, `8fb8365`)

- **Major, fixed** (origin: pre-existing, partly fixed in round 2; kind:
  contract). GPT. A generic wrapper could declare itself plain while it
  wrote a secret child, so `encode` could return the secret in an
  ordinary `Vec`. Also, `encode_into` took a descriptor apart from the
  type. Since this fix, `Encode::encode` takes an encoder typed for its
  own value. A component is written only through `Encoder::put`, which
  checks at build time that the parent is secret whenever the child is.
  `encode_into` takes its descriptor from the type.
- **Major, fixed** (origin: pre-existing; kind: contract). GPT. A later
  plain encode could grow a buffer that once held a secret, and so
  release that block after only a best-effort wipe. `encode_into` now
  never grows, shrinks, moves or frees the caller's allocation, whatever
  the message. An allocated buffer that is too small gets
  `AllocationFailed`.
- **Major, fixed** (origin: fix round 2; kind: correctness). GPT, and
  the scoped check of the specification. Boxing a buffer with spare
  capacity shrinks it: an allocator request the ledger never saw, which
  can abort the process if it fails. The boxing helper again refuses any
  capacity other than the exact count. This reverses round 2's minor fix.
- Minors (GPT 2, GLM 1, scoped check 2; all fixed or forwarded):
  - errors raised before the first wipe left the buffer untouched, which
    contradicted the documentation (GPT and GLM); every call now starts
    with a wipe and every error ends with one;
  - the fixed-array ratios ignored the length, and an empty array
    reported non-zero ratios (GPT and the scoped check); they now take
    `N`, with zero for `N = 0`;
  - the wording of the specification's worked bound was forwarded to the
    specification's branch.

### Round 4 (fixes in `40c9877`, `38062dc`, `8a8539f`, by `claude-mythos-5-2`)

- **Major, fixed** (origin: fix round 3; kind: correctness). GPT.
  `Encoder::put` gave the child a copy of the count of bytes left, and
  copied it back only on a normal return. A parent that caught the
  child's unwind went on with a stale count, so it could grow the buffer.
  Now every encoder of one message shares one count. Each write is also
  held to the buffer's capacity. A drop guard wipes the buffer on
  unwind. The unwind tests were red before the fix.
- **Major, fixed** (origin: fix round 3; kind: contract). GPT. A type
  could be secret by its descriptor and plain by its encoding, and a
  plain parent could then write it through `put`. Secrecy is now one
  flag per type (`Classified`), and `Message` has no flag of its own.
  The encoder's check, the build-time refusal and the decoder's
  redaction all read that one flag. A compile-fail doc-test shows that a
  descriptor with a `secret` field does not build.
- **Major, fixed** (origin: pre-existing; kind: contract). GPT, and GLM
  as a minor. `decode` and `decode_traced` took a descriptor apart from
  the type. So a secret-bearing type could be decoded under a plain
  descriptor, with positions in its errors and a larger cap or budget
  than its proof. Both entry points, and `proven`, now take the
  descriptor and the secrecy from the type. The traced budget can only
  lower the type's own budget.
- Minors:
  - Fixed: two compile-fail doc-tests could fail for a reason other than
    the one they named (GPT and GLM). Error-code suffixes are not
    enforced on the stable toolchain, so each compile-fail doc-test now
    stands beside a passing twin that differs in one line.
  - Fixed: the wipe wrote spare capacity with `Vec::resize`, which has no
    documented no-reallocation guarantee (GPT). It now uses `push`.
  - Refuted, test strengthened anyway (GLM): GLM said the boxing test
    would pass without the capacity guard. The committed test had the
    discriminating shape. With the guard deleted, it fails.
  - Named limit (GLM): no build-time check can see whether a leaf's own
    bytes are secret. That flag comes from the cap table, so the
    generator must set it and test it. It is stated in `Classified`'s
    documentation.
  - Forwarded (GLM): the specification text that the new contract
    changes, for #42's branch.

### Round 5 (fixes in `dda55a7`, `0c46850`, `a909522`, `7df809f`, `6b260fd`)

- **Major, fixed** (origin: new code in this round's range, `99a3a7f`;
  kind: missing mechanism). GPT. `check-bans` proved the configuration
  nearest each crate. But clippy reads the directory `CLIPPY_CONF_DIR`
  names before any of them, and the workspace's clippy run inherited the
  variable. `check-bans` now refuses to run while the variable is set.
  `cargo xtask check` runs clippy with it removed, and a self-test case
  plants it.
- Minors (GPT 5, GLM 1; all fixed):
  - nothing required every root ban to have a planted line; it is now
    required;
  - an error that a secret decoder passed on from a decode of its own
    kept its position; the entry points now strip it;
  - the integration tests' crate-wide allocation exemption also hid the
    clock bans (GPT and GLM); the exemption now covers one helper module;
  - the unwind test still passed when the count went stale; it now
    leaves room that only the count refuses, and a mutant fails it;
  - the specification claimed redaction tests through both entry points
    that did not exist; they do now.

### Round 6 (fixes in `0baae1e`)

- **Minor, fixed** (origin: fix round 5; kind: missing mechanism). GPT.
  The coverage check skipped a ban array whose key was indented, which
  is valid TOML. It also skipped a root `.clippy.toml`, which clippy
  prefers to `clippy.toml`. The ban reader now reads an indented key
  and bracket. Any ban key or ban line in another form is refused with
  its line number. Coverage applies to a root configuration under
  either name. There are unit tests and self-test cases for an indented
  key, an unreadable entry and a root `.clippy.toml`.
- **Minor, fixed** (origin: fix round 5; kind: missing mechanism). GPT.
  A build script can set `CLIPPY_CONF_DIR` for its own crate's compiler
  (`cargo::rustc-env`), after `cargo xtask check` has removed it. A
  probe with the pinned toolchain showed that this works, and that
  setting `CARGO_MANIFEST_DIR` (where clippy's lookup starts) or
  `CLIPPY_ARGS` (its lint arguments) for the compiler works too. The last
  one silenced the bans outright. `check-bans` now runs the workspace's
  clippy and reads cargo's report of each build script's output. It
  refuses any build script that sets `CARGO_MANIFEST_DIR` or a variable
  whose name contains `CLIPPY`. It also checks every package, not just
  the members. The self-test builds a crate whose build script sets
  `CLIPPY_CONF_DIR` and proves it refused, beside one that sets another
  variable and passes. No workspace member has a build script today.

## Claude self-check (not a seat)

After round 6, the implementer ran a security pass, by the OWASP-based
security-audit method. It covered `crates/ironafs-xdr` and the new
`check-bans` code. Claude wrote this code, so the pass is not a review
seat. It is the author's own check.

Checked, with no defect found:

- **Untrusted input.** The decode paths are `run`, the cursor (`take`,
  `check_end`, `check_item_end`), `length`, `opaque`, `opaque_owned`,
  `array`, `fixed_array`, `fixed_opaque`, `fixed_opaque_owned`,
  `out_of_line`, `padding`, `read_bool` and `read_enum`:
  - every length and count is checked against its bound, its cap, the
    array limit and the input's end, before anything is reserved or read;
  - slicing goes through `get` and `first_chunk`;
  - the message cap is checked before anything is read;
  - trailing bytes are refused.
- **Panics.** There is no `unwrap`, `expect`, `panic` or indexing in
  non-test code; the workspace's clippy denies them. The build-time
  assertions (depth, inline size, `S_MIN` of at least one unit, and
  secrecy) are compile-time only.
- **Arithmetic.**
  - Ends and padded lengths are computed in 64 bits with `checked_add`.
  - Slot ratios use `checked_div` (a zero `S_MIN` gives `None`), then
    `div_ceil` and `checked_add`.
  - The ledger's request is a `checked_mul`, and its total a
    `checked_add`, before the budget comparison.
  - `proven` uses `checked_mul`.
  - The encoder's size pass uses `sum`, and each write takes its bytes
    from the shared count with `checked_sub`.
- **Memory bounds.**
  - Every decoder heap request goes through `Ledger::reserve`. That is
    `try_reserve_exact`, checked against the budget before it is made,
    and filled only by `push`.
  - Boxing refuses spare capacity, so no shrink happens outside the
    ledger.
  - Array elements are decoded by a loop, and the recursion depth is
    bounded by the type's `DEPTH`, checked against `DEPTH_MAX` at build
    time.
  - The encoder makes one request, only into a buffer with no
    allocation. Each push is held to both the count and the capacity.
- **Secret handling.**
  - `locate` adds no position in a secret-bearing message, and `run`
    strips one from any error passed on.
  - The `Debug` of `Decoder`, `Encoder`, `Ledger` and the borrowed
    wrappers prints no value or length.
  - `Error` holds only constants and, outside secret messages,
    positions.
  - The encoder wipes the buffer at the start of every call, on every
    error and on unwind.
- **`check-bans`.** Its subprocesses take fixed arguments. Fixtures live
  under the target directory. cargo's JSON goes through the crate's own
  parser, which has a depth limit. There is no indexing.

Found, fixed test first:

- **Hardening, fixed** (`4dffb9f`). The build-script check skipped any
  cargo message it could not parse. A build script's report in a form
  the parser could not read would have passed unchecked. Such a message
  is now refused. The unit test was red before the change.

Noted, not defects of this crate (each rests on the generator, as the
specification says):

- the build-time inline-size check covers the message type only; each
  generated type's own assertion (5.2, point 10.1) is the generator's;
- a recursive type is forbidden by the profile (5.1, point 4); a
  handwritten `Decode` that understated its `DEPTH` could recurse on
  input;
- a leaf's own secrecy flag, and whether a secret-bearing message's
  decoder borrows rather than copies, are the generator's to set and
  test (`Classified`, "Limits").
