# Review record: the network-generation source, part 1

## The change

Class S. Issue #97 (plan id M2a-71), part 1. Part of #97. Based on #57
part E (`m2a-57-ose`), which is reviewed separately.

- `docs/specs/network-generation.md`, written before the code.
- `ironafs-netgen`, a new pure crate, holding:
  - the bounded generation counter;
  - seven required consumer hooks, called before each publication;
  - the route-netlink decoder;
  - the monitor's state machine: the snapshot, the barrier, the dirty
    rule, and the losses that withhold the generation.
- `ironafs-net`: the Linux monitor's two threads over `linux-rtnetlink`,
  with wakes and a handle that joins them.
- `ironafs-os`: the notify socket joins the nexthop group.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

### Round 1, GPT

- > major crates/ironafs-net/src/monitor.rs:163 | The driver finishes and publishes a snapshot before reading the notify queue. It then applies older queued records to the fresh tables, even after an overflow has made that queue incomplete.

  Fixed (c78e676, 1693285). After any loss on the notify socket, the monitor asks for no dump until the driver has made that socket again (`needs_subscription`, `subscribed`). Shown red with a plant.

- > major crates/ironafs-netgen/src/monitor.rs:258 | After startup, a loss publishes a readable generation before starting recovery. ADR 0005 sheet 23 requires a fresh verified snapshot before reusing state.

  Fixed (c78e676). A loss withholds the generation (reads fail) until the fresh snapshot completes. Shown red with a plant.

- > major crates/ironafs-netgen/src/monitor.rs:175 | Link-change suppression compares only four flags and operational state. It ignores `IFLA_GROUP`, even though an existing `suppress_ifgroup` policy rule uses the link's group to accept or reject a route.

  Fixed (c78e676). Link suppression also compares `IFLA_GROUP`, `IFLA_MASTER` and `IFLA_IFNAME`. Shown red with a plant.

- > major crates/ironafs-net/src/monitor.rs:193 | A dump waits indefinitely for a matching reply while holding the state lock. During that wait the driver cannot read notifications, and `resumed()` cannot acquire the lock. The eight-failure cap only counts failures that return.

  Fixed (1693285). The driver has two threads, no dump is held under the lock, and `resumed()` only records the loss.

- > major crates/ironafs-netgen/src/monitor.rs:216 | The request path ignores `NLMSG_OVERRUN`, first by sequence and then through the catch-all arm for a matching sequence. It also commits the address snapshot immediately on `NLMSG_DONE`, bypassing validation of any remaining bytes in that datagram.

  Fixed (c78e676). Each dump datagram is checked whole first, and `NLMSG_OVERRUN` of any sequence fails the dump. Shown red with a plant.

- > major crates/ironafs-net/src/monitor.rs:95 | If a hook unwinds in `resumed()`, the call leaves the mutex poisoned and the old generation readable. The driver's lock helper recovers the state without stopping it. On the monitor thread, the exit guard calls the same hooks again during unwinding.

  Fixed (c78e676, 1693285). A loss withholds the generation before hooks run. A poisoned lock, or a thread unwinding from a hook, halts the source without calling the hooks again. New test; shown red with a plant.

- > major crates/ironafs-net/tests/it/monitor.rs:211 | The root-run overflow test writes its batch through a predictable PID-based path in the temporary directory. CI isolates the network namespace and shares the filesystem.

  Fixed (1693285). The burst goes through `ip -batch -` on standard input. The same pattern in #57 part E's own test belongs to that branch.

- > minor crates/ironafs-net/tests/it/monitor.rs:102 | The last hook sends its observation before publication, but `wait_for` immediately expects publication. Later, `drain` may discard part of a seven-hook batch. Any queued `Changed` event can satisfy the next address, route, or rule assertion.

  Fixed (1693285). `wait_for` waits for publication, and each change gets a fresh monitor.

- > minor crates/ironafs-os/sites.json:942 | Group 32 and bit 31 match the Linux 5.3 UAPI. The ABI probe now requires `RTNLGRP_NEXTHOP` by name, so it cannot compile against unbackported pre-5.3 headers. The cited manual documents the mask but does not establish how older kernels handle this unused bit at bind time. [Linux 5.2 UAPI](https://raw.githubusercontent.com/torvalds/linux/v5.2/include/uapi/linux/rtnetlink.h), [Linux 5.3 UAPI](https://raw.githubusercontent.com/torvalds/linux/v5.3/include/uapi/linux/rtnetlink.h), [netlink(7)](https://man7.org/linux/man-pages/man7/netlink.7.html)

  Partly accepted. The ABI check names `RTNLGRP_NEXTHOP` on purpose, so build headers must be from Linux 5.3 or later, or carry the backport. The old-kernel bind is UNVERIFIED (spec Q5); if it fails, the monitor does not start, which fails closed.

- > minor crates/ironafs-netgen/src/netlink/tests.rs:325 | The prefix sweep discards every decode result. It checks for panics on the sampled inputs but never asserts that an accepted prefix contains only complete messages, as spec §10 claims. The seeded sweep also leaves C4's decoder fuzzing requirement open.

  Fixed for the sweep (c78e676). The fuzz target stays MISSING (spec Q2).

### Round 2, GPT

- > major crates/ironafs-netgen/src/monitor.rs:198, :262, :368 | Snapshot completion overwrites link and address changes already processed by the notify thread. For example, the link dump records group A, a notification changes it to B before the address dump completes, and completion restores A to the comparison table while the actual group is B.

  Fixed (10d547d). A link or address notification during a snapshot makes it dirty, and the snapshot is retaken (counted as a failure), never merged. Narrowed: route, rule and nexthop notifications leave it, since the tables hold neither.

- > major crates/ironafs-net/src/monitor.rs:186, :204, :215, :249 | Both workers are detached. Stopping wakes the condition-variable waiter, but it cannot interrupt either socket receive. A notify worker on a quiet network remains blocked after handle drop. A snapshot worker blocked on an abandoned request also cannot act on a resume, a new subscription, or a stop until that receive returns. A caller-side hook panic can additionally skip the wake at line 118. [recv(2)](https://man7.org/linux/man-pages/man2/recv.2.html)

  Fixed in part (4b8da7e). Stop, loss and resume send wakes, and `resumed()` wakes from a drop guard. Round 3 found that shutdown still relies on a single wake (B1).

- > major crates/ironafs-net/src/monitor.rs:215, :219, :249, :252 | The notify receive can return ENOBUFS before the notify worker takes the state lock. The snapshot worker can win the lock in that gap, process the address terminator, and publish while the already-returned loss is still pending. [netlink(7)](https://man7.org/linux/man-pages/man7/netlink.7.html)

  Fixed (10d547d, 4b8da7e). The snapshot thread no longer publishes; the notify thread publishes on the barrier's acknowledgement.

- > major crates/ironafs-netgen/src/monitor.rs:243, :259, :272, :281 | The whole-datagram pass checks decoding and overrun only. An address NLMSG_DONE followed by a decodable NLMSG_ERROR for that same sequence passes the first pass and publishes before the error is processed. The link path also changes the expected sequence immediately, so a trailing error for the old sequence is skipped. The manual defines DONE as the last header of a multipart reply. [netlink(7)](https://man7.org/linux/man-pages/man7/netlink.7.html)

  Fixed for the same-sequence cases (10d547d). Round 3 found the next-sequence case (B4).

- > minor crates/ironafs-net/tests/it/monitor.rs:204, :216, :232 | A fresh subscription removes earlier test traffic, but the address operations can themselves create or remove prefix routes. The test accepts the first generic Changed move, so a route notification from the same operation can satisfy an address assertion. [ip-address(8)](https://man7.org/linux/man-pages/man8/ip-address.8.html)

  Fixed (10d547d, 4b8da7e). `Cause::Changed` names its kind, and the test waits for that kind.

- > minor crates/ironafs-net/tests/it/monitor.rs:155, :187 | The shared-host startup test still requires the current generation to be exactly 1 after the first publication. The new drop test requires the next seven queued observations to be Stopped. An unrelated change after startup can break either assertion.

  Fixed (4b8da7e).


### Round 3, GLM

- > minor crates/ironafs-net/src/monitor.rs:289 (follows) with crates/ironafs-netgen/src/monitor.rs:220 (request gate) | follows() cannot distinguish 'the address dump ended in order' (request() == None because the barrier phase began) from 'the dump was abandoned mid-flight by a notify-socket loss' (request() == None because !subscribed gates it). On the second path — e.g. the notify thread takes an overflow loss while the snapshot thread is blocked receiving the address dump's answer — the inner loop breaks with next == None, follows(address-dump, None) is true, and renew() is skipped, so the next (post-resubscription) links dump is sent on the same request socket while the abandoned address dump may still be running in the kernel. The spec's own rule (5.7 point 7: a dump that does not end in order leaves the kernel's dump running, so the socket is made again) is not upheld on this path.

  Fixed (6978716). An address dump that ends with neither a further dump nor a barrier was abandoned, and its request socket is made again. INSPECTED only: the path is a race, with no deterministic test.


### Round 3, GPT

- > major crates/ironafs-net/src/monitor.rs:121, :158, :263, :300, :327, :349 | Shutdown and recovery depend on a single netlink wake. The driver ignores wake send errors and has no fallback if the kernel reply is lost. A panic in a stop hook also skips `wake_all()`. After a successful barrier send, `barrier_sent` suppresses retries and there is no deadline for its ACK. Netlink documents that kernel-to-user messages can be lost. [netlink(7)](https://man7.org/linux/man-pages/man7/netlink.7.html)

  **B1, blocker before merge.** Intended fix: the stop path sends wakes again until both threads have ended; a guard wakes even when a stop hook panics; and the barrier's acknowledgement gets a deadline through the clock seam, after which the snapshot is retaken.

- > major crates/ironafs-netgen/src/monitor.rs:248, :289, :306, :472; crates/ironafs-netgen/src/netlink.rs:289 | The notify handler publishes on any `NLMSG_ERROR` with the barrier sequence. It ignores the status, accepts a body missing the echoed request header, and calls `complete()` before examining the rest of the datagram. A later link or address record, overrun, or malformed record cannot prevent that publication. A successful ACK has status zero. [netlink(7)](https://man7.org/linux/man-pages/man7/netlink.7.html)

  **B2, blocker before merge, partly disputed.** Accepted: the barrier's acknowledgement must have status 0 and carry the echoed `NLMSG_NOOP` header, and the datagram is checked whole before the snapshot completes. Disputed: records after the acknowledgement in the same datagram were queued after it, so applying them after publication follows the kernel's order and leaves no gap. A later overrun withholds the generation again.

- > major crates/ironafs-net/src/monitor.rs:158, :263, :282; docs/specs/network-generation.md:180 | A consumer hook that drops the handle runs with the state mutex held. `Drop` calls `stop()` and tries to acquire that same mutex before reaching its worker-thread check.

  **B3, blocker before merge.** Intended fix: `Drop` checks whether it runs on a worker thread before taking the lock. On a worker it only records the stop, in an atomic that the worker applies after the hook returns.

- > major crates/ironafs-netgen/src/monitor.rs:324, :339, :355, :372 | The validation pass pins the outstanding sequence, but the application pass changes it midway through the datagram. A link `NLMSG_DONE` followed by a `NLMSG_DONE` with the next sequence advances the monitor to the barrier even though the address request has never been sent.

  **B4, blocker before merge.** Intended fix: the application pass stops at the outstanding dump's terminator, so nothing after it in that datagram is applied under a new sequence. The severity is disputed, not the defect: only the kernel's datagrams reach the decoder, and the kernel answers only requests that were sent, so the next sequence cannot appear before its request. The logic is still wrong, and it is fixed.

- > minor crates/ironafs-net/tests/it/monitor.rs:187 | The drop test blocks waiting for channel closure after `drop(handle)` returns.

  Disputed. Waiting for the channel to close is how the test asserts that both threads ended. If they never end, the runner terminates the test, and that is a failure (coding standards rule 15: a hang is a failure).
