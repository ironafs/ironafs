# Review record: the scheduled workflows and the freshness check

## The change

Part of issue #75 (plan id M2a-84): the class I half of its pull request
(a). The issue carries class S, so the change had the class S seats.

- `cargo xtask freshness` and its `--self-test`: for each scheduled tier
  (nightly, 2 days; weekly, 8 days), the tier's manifest
  `tests/tiers/<tier>.txt` and the GitHub API, read through `gh api --jq`.
  A run counts only if it is a scheduled run of the tier's workflow on
  `main`, judged by its first attempt: complete when, for every manifest
  id, a job of that name ran a step `run <id>` that succeeded or failed.
  Exit 1 for a stale or incomplete tier, 2 when nothing could be verified.
- `.github/workflows/nightly.yml` and `weekly.yml`: no `concurrency` key,
  each job `contents: read` only, no secret, no artefact, no cache; each
  runs one manifest item, `build`, until the jobs the spec names exist.
- `.github/workflows/freshness.yml`: the live check on pull requests,
  pushes to `main` and its own schedule, advisory (`ci-ok` does not depend
  on it). The self-test runs in `ci.yml`'s lint job.
- Not in this change, and not reviewed here: the `xtask` runner (capture,
  classification at capture, seed drawing, redaction) and the reporter,
  both class S and both still owed to #75; the fuzz jobs and the fuzz
  manifest check (#45); the coverage job (#74); links to a first nightly
  and weekly run, which exist only after the merge.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## Decisions

Taken by the controller and recorded here:

- **No public scheduled artefacts** (`docs/specs/testing.md`, 5.5, points
  2 and 6): no scheduled job uploads an artefact or uses a cache,
  encrypted or not. The spec, as the contract, supersedes the issue
  body's encrypted fuzz-crash upload and result-file artefact; the issue
  gets a correcting comment once the owner approves its text.
- **The placeholder `build` jobs** stand until the runner exists: running
  the test suite in a public scheduled job before then would stream test
  output to the log (5.5, point 2).
- **`actions: read` on the freshness job** is accepted: it is read-only
  and needed to list runs and jobs, which on a public repository anyone
  can read. The job runs the pull request's own `xtask` with it.
- **Only `schedule` runs count**, not dispatched ones, so manual runs
  cannot hide a schedule GitHub disabled.

## Findings

GLM, round 1:

- **Minor, fixed (`90ca627`):** the run and job lists were read one page
  of 100 only, so a run with more than 100 jobs (one fuzz job per target
  makes that foreseeable) could never be judged complete. Both lists are
  now read page by page, up to 10 pages (the API's 1,000-result limit);
  the run list stops at the first page that reaches past the tier's age.
  A list still short after the cap is refused.
- **Minor, fixed (`90ca627`):** a failure of `cargo metadata` exited 1,
  the status for a stale tier. Every error other than a stale or
  incomplete tier now exits 2.

Gemini, round 1:

- **Minor, fixed (`90ca627`):** `gh`'s output and the parsed records were
  unbounded. Each page of output is capped at 4 MiB, a page may hold at
  most 100 runs or jobs, a job at most 1,000 steps, and lines are split
  into a bounded number of fields.
- **Minor, fixed (`90ca627`):** the workflow-rules test found jobs by
  their `name:` lines and permissions only as an exact block header. It
  now reads each job key under `jobs:`, requires its `name:`, its
  `permissions:` block and its `run <id>` step, and checks every
  `permissions` key in any form (block, `write-all`, a flow map); the
  planted workflow shows each form caught.
- **Minor, fixed (`90ca627`):** the self-test used its own copy of the
  nightly tier. It now runs every case for every tier of the check's own
  list, with planted times one second either side of each tier's age
  (checked against the list, so a tier without them, or a changed age,
  fails it), and adds the missing plants: manifest ids that are not
  lowercase words, a malformed run line, a job whose steps ran without its
  `run <id>` step, and a renamed job with the job count unchanged.

The review stopped there: both seats passed, and each minor finding is
fixed. The fixes were not re-reviewed (minor findings only).
