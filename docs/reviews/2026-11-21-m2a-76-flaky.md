# Review record: the flaky-test rule and the retries check

## The change

Class P. Issue #76 (plan id M2a-85).

- `docs/coding-standards.md`, rule 15:
  - No test is ever retried. `cargo xtask check-retries` fails on any
    profile, per-test override, command or environment that sets retries
    above 0.
  - A timeout override cites measured times. Heavy tests join a
    thread-capped test group, and a crate that runs the simulator has a
    terminating per-test override.
  - A new item, "A flaky test is a bug", covers four things: the issue
    with its seed, machine and both runs; the pull request that waits for
    it; a failing simulator seed as a reproducer; and quarantine, which
    needs an issue and the owner's decision and keeps the test in the
    inventory, marked.
  - The details are cited from `docs/specs/testing.md`, 5.4, points 5
    and 6, not restated.
- `cargo xtask check-retries` reads every place nextest takes a retry
  policy from:
  - the profiles and per-test overrides in `.config/nextest.toml`, through
    a small TOML reader;
  - the commands and environments under `.github/` and in every cargo
    configuration file;
  - the Rust source of `xtask`, except the check's own files.

  In the profiles only `retries = 0` passes: any other value fails, and
  so does `retries` as a table in any spelling. In commands, the option
  and the variable must be followed by a plain 0. An option that points
  nextest at another configuration file fails, as does an escape that
  spells a character of a name or a line-ending backslash that could join
  one. A missing profile file or `xtask` source fails.
- `--self-test` passes a clean fixture and catches each planted violation.
  `cargo xtask check` and CI's lint job run the check and its self-test.
- The comment in `.config/nextest.toml` now matches the rule.
- **Written by** `claude-code:claude-opus-5-5` (the change, and the fixes
  of every round).

## Findings

Round 1, all fixed in `8128066`:

- **Major, fixed:** `retries` written as a table header
  (`[profile.ci.retries]`) or as a non-final dotted key (`retries.count`,
  in a profile, an override or an inline table) passed the check, though
  nextest reads it as a retry policy. Each form was confirmed on a scratch
  crate with nextest 0.9.143: the table header, the dotted keys, an
  override's dotted keys, the inline table, a quoted key and an escaped
  key each made nextest retry a failing test. The check now fails
  `retries` as a table in any spelling, and allows only `retries = 0`. It
  has one planted case for each form, and a control for `retries` used as
  a value.
- **Minor, fixed:** a value joined to a quoted 0 (`--retries "0"1`,
  `NEXTEST_RETRIES='0'2`) passed, though a shell joins it into another
  number. The value is now read to a real delimiter with its quotes
  kept, and passes only as a 0 alone or closing its own quotes.
- **Minor, fixed:** escapes evaded the check, and a line-ending backslash
  miscounted lines. Two kinds of escape got through: those in a quoted
  TOML key (`"retries"`, which nextest honours) and those in a cargo
  configuration string. The TOML reader now decodes escapes as TOML does,
  refuses an escape TOML does not define, and counts the lines a
  line-ending backslash joins. In command files, which are read as raw
  text, an escape that spells a letter, digit, `-`, `_` or `=` fails.
- **Minor, fixed:** two parts.
  - The check read `xtask`'s test run from the compiled constant. That
    missed any other nextest command in `xtask`, and a self-test could not
    plant one. The check now reads `xtask`'s Rust source under the root.
  - A file elsewhere ending in `.config/nextest.toml` could stand in for
    the missing profile file. The profile file is now found only at its
    exact path.

Round 2, all fixed in the commit that adds this record:

- **Minor, fixed (in part, by design):** backslash handling in command
  files. Four parts:
  - A doubled backslash was consumed as a pair. In a YAML double-quoted
    string it is one backslash to the shell, which may still decode the
    escape after it. A run of backslashes is now read at its last one.
  - A line-ending backslash right after a name's character could join an
    option across lines. That now fails as its own violation. A shell
    line continuation after a space passes, and so does the `\n\`
    continuation of a Rust string.
  - A braced escape stopped at a `_` separator (`\u{7_2}`). Separators are
    now read through to the closing brace.
  - Left as it is: a Windows path segment such as `\x64` in a workflow
    still fails as an escape. That keeps the check failing closed; no
    such path exists in the repository, and a workflow can write the path
    another way.
  - Not taken: decoding cargo configuration strings with the TOML reader.
    The raw-text match and the escape rule already fail every spelling
    the review named.
- **Minor, fixed:** a backtick after a 0 was always taken as closing a
  code span, so `--retries 0` followed by a backtick command substitution
  passed. A backtick now closes the value only when one opened right
  before the option or variable. Prose that ends a sentence with
  `--retries 0.` or `--retries 0:` no longer fails; `0.5` still does.
- **Minor, fixed:** a multiline TOML string may end with one or two
  quotes of its own before the closing delimiter, and the reader ended it
  early. Paired four- and five-quote strings could then hide a
  `retries = 2`. The reader now takes those quotes into the string and
  refuses a sixth.

Each fix of both rounds has a planted test that fails with the fix
reverted, and a `--self-test` case. Gemini's uncertain items, in both
rounds, were the checks it could not run and the files it was not given.
The checks were run (Evidence); the files are unchanged by the findings.

## Named limit

The check reads text. A shell can still assemble an option or a variable
at run time, for example from two shell variables, and no text check sees
that. Review of every change to a workflow, a cargo configuration or
`xtask`, which the rule's review seats already require, is the defence
there.
