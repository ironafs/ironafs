# Review record: volume location and file-service reads, and operation grants, the version from documents only

## The change

Class S. Issue #65 (plan id M2a-03).

- `docs/specs/vl-fs-read.md`: the nine volume location and file-service
  procedures M2a calls for reads, by role; caps on every message and
  variable-length field; a hostile-input rule for every decoded field;
  checks of each reply against its own request (fetch length, object
  kind and size rechecked on the reply's own status record, bulk counts);
  the variant memo with its bounds; the static fallback catalogue
  entries (64-bit to 32-bit fetch, inline bulk to bulk status, either
  bulk to one status call per file, no fallback for the volume location
  lookups); the classification of abort codes by procedure and service;
  the evaluator that turns an access mask and mode bits into operation
  grants (granted, denied or undecided, unknown bits granting nothing);
  the arithmetic, a closed error set, tests, and open questions Q1 to
  Q12.
- `docs/specs/README.md`: register of editions rows E7 to E12, and the
  index row.
- **Written by** `claude-code:claude-opus-5-5` (drafting, and the fixes
  of every round).

**This is the documents-only version.** No admissible document gives the
argument and result layouts of these procedures, so every layout point
is MISSING or UNVERIFIED, and nothing is coded from it. The reviews below
judged the rules that do not depend on the layout (caps, hostile-input
rules, the catalogue, the error mapping, the grant rule) and the
labelling; they did not and could not judge any wire value. Issue #65
stays open: it closes only when the revision backed by the observation
lab's stage C captures (#51) is reviewed and accepted (section 13, Q1;
ADR 0004, C6, point 3).

## Findings

### Round 1, GLM (all fixed in `81d3857`)

- **Major:** the variant memo had no cap or eviction, and was created
  from forgeable input (a decoded reply or an abort). Fixed: only
  refusals are stored, per catalogue entry; a decoded reply to the
  preferred procedure deletes the memo; caps of 64 memos per context and
  1 024 in total, with least-recently-used eviction, which only restores
  the preferred procedure (5.2; 5.6, point 2; test C5).
- **Minor:** section 3 said eight procedures and listed nine. Fixed.
- **Minor:** 5.6, point 1 forbade delivery without a grant while 5.7,
  point 7 delivers once without one. Fixed: 5.6, point 1 names the
  exception.
- **Minor:** a bulk reply that failed to decode had no fallback. Fixed:
  F3 now covers `ReplyInvalid` and rejected items.
- **Minor:** the single and bulk status caps assumed different record
  sizes. Fixed: one allowance per status record and per callback
  promise sets both.
- **Minor:** the abort table's procedure columns were inconsistent, and
  one named a per-item failure whose form is unknown. Fixed: each row
  names its scope, and a new row covers the address-list call.
- **Minor:** the decision source row omitted C7, C16 and N29. Fixed.

### Round 1, Gemini (all fixed in `81d3857`, one in part refuted)

- **Major:** the variant memo collided between catalogue entries and was
  unbounded. Fixed as GLM's major; the key now includes the entry.
- **Major:** link and directory caps were checked only before a fetch,
  and the reply's object kind was not checked. Fixed: the reply's kind
  must match; the caps are checked again on the reply's own status
  record; a link is read whole, with one re-fetch if its length changed,
  never as a prefix; an object read in several fetches keeps one data
  version (5.4, point 9).
- **Major:** the evaluator's inputs and outputs contradicted point 7 and
  test G1, and the dropbox case needed inputs the evaluator does not
  take. Fixed: the evaluator takes only the file type, the caller's mask
  and the mode, and answers granted, denied or undecided per operation;
  attributes, statistics and the rights report are not its output;
  undecided operations go to the reader's own fresh, uncached call; the
  dropbox case moves to the ACL specification (5.7).
- **Major:** the bulk fallbacks were triggered too narrowly and too
  broadly, and misaligned items could not be detected. Fixed: F2 only on
  the "unknown procedure" abort; F3 on either bulk call's count, decode
  or item failures and on aborts that concern one file; volume-wide and
  server-wide aborts are classified once for the listing; until Q5, any
  rejected item discards the whole reply (5.4, point 10; 5.8).
- **Major:** the volume status procedure had no hostile-input rules, a
  volume id of 0 was refused in only one request, and the address rule
  let loopback and reserved ranges through. Fixed: 5.4, point 14; a
  volume id of 0 refused in every request; loopback (outside a
  loopback test venue), this-network, link-local, multicast and reserved
  addresses unusable.
- **Minor:** abort handling for the address-list call, and missing error
  kinds. Fixed: row R24, and four new kinds in section 7.
- **Minor:** some wire shapes were stated as facts. Fixed: record sizes,
  each procedure's result composition and each status field's presence
  are labelled UNVERIFIED. In part refuted: the reference page cited
  lists the release clone id among the lines it takes from the volume
  location entry, so that role stays as a lead; its wire carriage is now
  UNVERIFIED and in Q8.
- **Minor:** several small consistency points. Fixed: the procedure
  count; the claim and source tables; the allowlist question's scope;
  the UUID octet mapping; a per-call fetch reply limit; item caps on bulk
  replies; a bound on address-list calls per lookup.

### Round 2, GLM (both fixed in `33a054b`)

- **Minor:** three places still called a record fixed. Fixed.
- **Minor:** the "unknown procedure" row said it sets a memo for every
  catalogue entry, though memos exist only for F1 and F2. Fixed.

### Round 2, Gemini (all fixed in `33a054b`)

- **Minor:** a link of length 0 led to a refused 0-byte request rather
  than a rejected reply, and an empty file's undecided read could do the
  same. Fixed: a link of length 0 is `ReplyInvalid`; an empty file or
  directory needs no data fetch; the status length bounds reply data,
  never the request.
- **Minor:** an undecided `search` was decided by a fetch, against the
  rule that access answers come only from a grant; test G2 used "the
  output" loosely. Fixed: `search` is not granted when undecided, like
  `execute`; G2 now speaks of the grant.
- **Minor:** two abort rows lacked the bulk fallback, and the
  address-list bound could be spent on sites of another version. Fixed:
  rows R21 and R22 name F3; address lists are fetched only for candidate
  sites of the version asked, once per server identity.

An uncertain item of Gemini's round 2 (control characters beyond
0x20 and 0x7F) was also taken: the display rule now escapes U+0080 to
U+009F and every octet of text that is not valid UTF-8.

Both lanes listed facts they could not check without the sources (the
registry's numbers and codes, the drafts, the reference pages and the
hashes in rows E7 to E12). They raised none as a finding; each such fact
is labelled UNVERIFIED in the specification. GLM could not read issue
#65 itself; the specification maps the issue's outcome and acceptance
list in sections 1, 2 and 12.2, from the issue's text.

## Clean-room note

No source code, test data or interface definition of any AFS or Rx
implementation was read for this change. The public documents read are
listed in the register (rows E7 to E12) with their hashes, and the Rx
draft only as the excerpt that leaves out its "Historical Implementation
Notes" section ("RPC Layer" and part of "Rx Connections").

Two of the public Internet-Drafts read contain code under another
licence:

- draft-keiser-afs3-xdr-primitive-types-01 shows a C structure under the
  IBM Public License in §4, beside the prose that the specification
  cites. It was seen while reading §4.
- draft-keiser-afs3-capabilities-00, Appendices A and B, which the draft
  states are excerpts of an implementation's interface definitions.
  Appendix A and the start of Appendix B were displayed and read before
  this was noticed.

Both are excluded by name in the register; nothing in this change is
taken from them, and the exposure is logged. The facts they repeat are
taken only from the drafts' prose and the registry, and stay
UNVERIFIED. Neither was opened again in the review rounds.

## Open items for the owner

  Registry's procedure numbers, service ids and error codes (register
  row E7) may be allowlisted, for the rows whose source is a release or
  a registration request. The specification recommends it and
  allowlists nothing until decided; every number stays UNVERIFIED, and
  no code waits on it, because a confirming capture is itself a route
  (ADR 0004, N31, point 1).
- **The excluded code sections** above: what, if anything, that
  exposure requires under ADR 0001.
- **Claims cited only through the claim record** (`[DES-057]`,
  `[DES-058]`): whether such a citation needs its own register row. The
  specification states how each is cited (section 12.2).
