# Review record: the namespace (mount points, volume selection and `@sys`), the version from documents only

## The change

Class S. Issue #80 (plan id M2a-63).

- `docs/specs/namespace.md`:
  - the mount-point target decoder: a byte cap, a strict grammar and
    every form it refuses;
  - the depth and cycle rule at the owner's bound (crossing 32 allowed,
    33 refused, a repeated mount point refused at any depth), with
    where the count starts and its compatibility cost;
  - volume selection per requesting context (rows S1 to S7), with no
    silent change of version;
  - the two-node model (a mount-point node the layer holds, a root node
    per context) and the rules that keep ancestors in the node table;
  - per-context bindings, with the chosen version held only in each
    context's own binding, and a fail-closed outcome when a binding
    does not lead to the root on the path;
  - the dynamic root's names, `.` and `..`, `@sys` and `@cell`
    substitution, and the default system-name list per M2a target;
  - the fail-closed outcome for a credentialed crossing with no
    authenticated volume location lookup;
  - arithmetic, a closed error set, security, tests, and open questions
    Q1 to Q10.
- `docs/specs/README.md`: the index row, register of editions rows E58
  to E60 (numbered after E57, the last id of the register landing order
  for the open specification branches), and row E9's "Cited by" and
  "Corroboration" columns.
- **Written by** `claude-code:claude-opus-5-5` (drafting, and the fixes
  of every round).

**This is the documents-only version.** No admissible document states
how a mount point is marked or stored in the file service, a volume
root's file id, or the default system-name list a clean client starts
with. Those points are MISSING, and nothing is coded from the decoder,
the root node keys or the default list until the observation lab (#51)
settles section 13, Q1, Q2 and Q5. The reviews below judged the rules
that do not depend on those facts and the labelling; they did not and
could not judge any stored byte. Issue #80 stays open (this pull request
is part of it): its outcome needs the `@sys` default per target, from a
clean reference client or the owner's choice (Q5).

## Findings

### Round 1, Gemini (all fixed in `c781a9b`)

- **Major:** a lookup on a mount point did not match section 5.7, and
  node identity before and after a crossing was undefined. Fixed: the
  two-node model (a mount-point node the layer holds, the same in every
  context; a root node per context, never given to a layer) and one
  rule for `..`.
- **Major:** the inline anchor chain could not survive eviction of the
  nodes `..` needs. Fixed: ancestors stay in the node table while a node
  names them (5.6.1, point 8).
- **Major:** the decoded target was bound to the location cache's
  lifetime instead of the mount-point object's own validity. Fixed:
  three entries with separate keys and lifetimes, and every step through
  a mount point rechecks the grants (5.6.2, points 8 and 9).
- **Major:** a version id of 0 was refused only on rows S1 and S2. Fixed:
  `VersionAbsent` on every row and for both dynamic-root names.
- **Major:** links climbing with `..` could re-cross mount points. Fixed:
  one visited set per request, refusing repeats and capping total
  crossings and hops (5.6.1, point 7; SMB only).
- **Minor:** `/afs/@sys` had no directory object to look in. Fixed:
  matched in memory against the names the root lists, with no discovery.
- **Minor:** the decoder's order checked octets before removing the
  terminator, and the pure decoder called the configuration crate.
  Fixed: the terminator first; the cell-name rule applied by the caller.
- **Minor:** register columns and cross-references. Fixed.

### Round 1, DeepSeek (all fixed in `c781a9b`)

- **Major:** the decoder's check order (as Gemini's minor). Fixed.
- **Major:** a VL entry whose read-only sites were all filtered made the
  volume "not replicated", so the read-only path fell back to read/write.
  Fixed: "replicated" means a read-only id that is not 0; unusable sites
  fail the crossing `offline`.
- **Major:** `VersionAbsent` (as Gemini's). Fixed.
- **Major:** the null-class scope against ADR 0004 C19. Fixed: C19,
  point 1 quoted and mapped; kept entries rest only on authenticated
  replies in the context; the question of authenticated VL lookups
  became Q10.
- **Minor:** a volume whose own base name ends in a version suffix.
  Fixed as a stated compatibility cost, with Q8; refusing every suffixed
  target was rejected, since it would refuse every read-only and backup
  mount point.
- **Minor:** `..` after eviction (as Gemini's major). Fixed.
- **Minor:** test N3 asserted the wrong identity. Fixed.
- **Minor:** a wrong cross-reference, and register row E9's
  corroboration column. Fixed.

### Round 2, DeepSeek (all fixed in `22f34ae`)

- **Major:** root nodes, which hold the anchor chains, were kept by
  nothing. Fixed: every node records its containing root, and a node
  stays while another names it as parent, anchor or containing root, or
  a binding names it; the bound is restated.
- **Major:** Q10 left an authenticated crossing on a real cell with no
  defined outcome. Fixed without changing ADR 0004: the crossing fails
  closed with `LocationUnauthenticated`, reported as `SecurityFloor`;
  the consequence is stated (5.6.2, point 10), and Q10 became an owner
  question with options.
- **Minor:** the round 1 dispositions (a summary; no change).
- **Minor:** overlapping `..` rules. Fixed: one rule; `..` is never a
  root node.

### Round 2, Gemini (all fixed in `22f34ae`)

- **Major:** the same root-node retention gap, and the containing
  version described as part of the mount-point identity. Fixed with
  DeepSeek's major; the lookup grant for a mount point in a volume's
  root directory is checked on the root node.
- **Minor:** error classification when read-only sites fail, the
  dynamic-root entry's binding and attributes, a test's wording and
  stale cross-references. Fixed.

### Round 3, Gemini (fixed in `9bb31ec`, the scoped round)

- **Major:** the version chosen was stored on the shared root node, so an
  anonymous context's forged VL reply could steer an authenticated
  context, and the choice outlived one unauthenticated request against
  C20, point 1. Fixed with Gemini's option (b): the version is held only
  in each context's own binding; an uncredentialed context keeps it only
  for its request; a credentialed crossing without its own authenticated
  binding resolves the containing volume with authentication first.
  Tests N9 and N10 cover both scenarios.
- **Minor:** the retention count in test N4 and the entry node's
  binding inputs. Fixed.

### Round 3, DeepSeek (PASS; minors fixed in `9bb31ec`)

- **Minor:** the round 2 dispositions (a summary; no change).
- **Minor:** the retention bound was short by the cell root's records,
  and a cell root's rebuild was not covered. Fixed: at most 2n records
  for a node with n path components; a cell root is rebuilt at the next
  use of its dynamic-root entry.
- **Minor:** an entry node's binding named a containing version it does
  not have. Fixed.

### Round 4, Gemini (all fixed in `bbd713e`)

- **Major:** the re-resolution rule did not say what happens when an
  ancestor resolves, in the requesting context, to a different root node
  than the one on the path, so a forged reply could still place a
  crossing in a volume the authenticated resolution never enters. Fixed
  with Gemini's stated fix: every cached binding and every step of
  re-resolution must lead to exactly the root node on the path; any
  other result stops the walk and fails closed with `AnchorMismatch`
  (reported as `stale`), without crossing. N9 and N10 cover distinct
  read-only and read/write ids, and a forged entry naming another
  volume.
- **Minor:** the order of the depth check and re-resolution, the entry
  binding left out of N4's count, and the order of tests N8 to N10.
  Fixed: the depth and repeat tests run first, on the stored chain,
  so a refused crossing sends no call. The finding's premise that the
  bound is 20 was wrong (it is 32); N4's depth-20 crossing is valid, and
  N4 now also states the refusal at 33.

## Q10, and the controller's decision

ADR 0004, C19, point 1 (Firm) forbids answering a request made under a
credential from routing obtained without authentication, and every VL
lookup in [vl-fs-read.md](../specs/vl-fs-read.md) is a null-class call.
As written, a credentialed request on a real cell therefore fails every
crossing with `LocationUnauthenticated` (5.6.2, point 10). M2a has no
credentialed requests on a real cell, so M2a is not affected. The
options (section 13, Q10): (a) authenticated VL lookups over the
context's own rxkad connection in M2b, checked in the lab; (b) an
ADR 0004 amendment to C19 for location data; (c) keep failing closed.

**Controller's decision (2026-11-21): option (a).** The VL lookups gain
an authenticated variant in vl-fs-read.md's M2b revision, and the lab
confirms that every VL server in the capture matrix answers them. Option
(b) is taken to the owner as an ADR amendment only if a supported VL
server refuses authenticated lookups. The owner may override this.
