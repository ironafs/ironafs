# Review record: `ironafs-vfs`, part 1, the contract's values

## The change

Class S. Part of issue #67 (plan id M2a-21).

- A new pure crate, `crates/ironafs-vfs` (`no_std` with `alloc`; it
  depends only on `ironafs-time`), holding the values that cross the
  contract between the core and the layers (ADR 0004, C7):
  - caller and handle capabilities with private fields, made only through
    `Mint`, and the operating system's attestation of a caller (C8, C13);
  - the error type: C46, point 1's 22 values plus the seven the contract
    specification adds (5.12, point 9), and how each reaches applications;
  - commit reasons (C9) and the reserved operations, refused as not
    supported (N46, point 1);
  - bounded extension lists (N41);
  - the invalidation stream: events, acknowledgements, `PurgeFailed`, and
    how pending effects merge and widen (C17; N47, point 3);
  - the ingress record of a request: arrival and cancel token (C39,
    point 3);
  - `Name`, an entry name's raw bytes, and the Linux name codec (L29,
    points 1 and 2).
- In `crates/xtask`: a check in `check-deps` that only `ironafs-vfs`,
  `ironafsd`, `ironafs-client`, `ironafs-sim` and `ironafs-test-support`
  name `Mint` (the contract specification, 5.11). It also refuses source
  those other crates could bring in unread, and refuses public items of the
  allowed crates that name the mint.
- In `crates/ironafs-test-support`: `Flag`, the hand-set watched flag, moved
  out of the seeded clock's tests so both crates share it.
- The branch merges `m2a-71-types` for `Stamp` and `WatchRef`, which the
  ingress record names. That merge is reviewed under its own record.
- Not in this change: the operations of C7, points 2 to 4, and their
  traits; the name codec's fuzz target, which lands with #45; the macOS
  and Windows name codecs.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## Findings

### Round 1, GLM

- **Minor (kind: contract not held by the type), fixed (`e76eec3`):**
  `Mint::new` is public, so any crate can mint capabilities. Fixed with a
  `check-deps` rule that only the allowed crates name `Mint`, proved by
  planted canaries and by a canary in the real workspace. The core's
  run-time record check stays owed by the brief that mints capabilities and
  by the scripted core (#98).
- **Minor (kind: duplicated test double), fixed (`aab9437`):** the `Watch`
  double in the ingress test copied the seeded clock's. It moved to
  `ironafs-test-support` as `Flag`, and the ingress test moved to
  `tests/it/`.

### Round 1, DeepSeek

- **Blocker (kind: compile-fail test), refuted as stated, then rewritten
  (`c3a6109`).** The finding said `HandleCap::clone(cap)` gives E0599, not
  the annotated E0277. On rustc 1.100.0 it gives E0277. The root point
  stood, though: stable rustdoc does not check error codes. So:
  - each compile-fail test now differs from compiling code only in the
    property it shows, and some have compiling twins;
  - the clone test is fully qualified, and new tests show no `Copy`
    (E0382) and no `Default`;
  - every block was compiled alone and had to give exactly its annotated
    error, and nightly rustdoc, which checks codes, was run as well;
  - a planted wrong code passed stable rustdoc but failed both of those
    checks.
- **Minor (kind: overstated documentation), fixed (`c3a6109`):** "a handle
  capability has one holder" was not what the type guarantees. The
  documentation now says the type is neither `Clone` nor `Copy`, that the
  value is not unique, and what holds the rest.
- **Minor (kind: predicate wrong for renames), fixed (`4324c4a`):**
  `Effects::covers` did not count a rename's two names. It now does, in
  either direction, and a single name never covers a rename.
- **Minor (kind: test not tied to the enum), partly fixed in `c3b5050`,
  completed in round 2.** The error list was not tied to the enum.
- **Minor (kind: boundary oracle used the code's constants), fixed
  (`c3b5050`):** the caps are now pinned with literals: 255 and 256
  bytes, 16 and 17 extensions, 4096 and 4097 bytes.

### Round 2, GLM

- **Minor (kind: check coverage overstated), fixed (`ab296ba`):** the mint
  check did not read source brought in by `include!` or `#[path]`, a
  procedural macro could build the name, and crates outside the workspace
  were not read. The crates outside the allow-list now may not use
  `include!`, `#[path]` (also in `cfg_attr`), or attributes and macro calls
  built from fragments. The procedural-macro and non-member routes are
  recorded as limits.

### Round 2, DeepSeek

- **Major (kind: check bypass), fixed (`ab296ba`):** a layer could
  `include!` a non-Rust file, or load one through `#[path]`, that names the
  mint. Refused as above, with five planted cases.
- **Minor (kind: test not tied to the enum), fixed (`8a87f31`):** a new
  error value could be given a position and left out of the list. One
  macro table now builds both the list and the exhaustive expectations,
  with literal positions. A new value with a wrong surface fails.
- **Minor (kind: check bypass through an allowed crate), fixed in part
  (`ab296ba`):** an allowed crate could hand the mint out. It now may not
  name the mint in a public re-export, function, constant, static, type
  alias, field or exported macro. Trait items, trait implementations and
  enum variants were recorded as limits. A test now ties each allowed crate
  to its kind.

Also in fix round 2, on the controller's direction, the crate was aligned
with the contract specification at `ba8517d`:

- the seven added error values (`a2a1fc4`);
- `PurgeFailed` (`4375ae1`);
- the per-binding `Revision` (`6a0e18b`);
- compile-fail tests that `Mint` has no `Default`, `Clone` or `Copy`
  (`7a62523`).

### Round 3, GLM

- **Minor (kind: check bypass through an allowed crate), open:** routes
  the token reader does not see: an `include!` inside an allowed crate, a
  private alias in a public signature, and a default type parameter. See
  "Open items".
- **Minor (kind: parsing), refuted, with a regression test (`9c47865`):**
  the finding said `pub extern "C" fn` leaves the ABI string between the
  qualifiers and `fn`, so the item is read as a field. The token reader
  drops string literals, so the string is never a token. A test shows an
  ABI function is read as a function. Another test shows why a non-name
  head is not refused: a tuple field `pub ::ironafs_vfs::Mint` is caught.

### Round 3, DeepSeek

- **Major (kind: check bypass through an allowed crate; missing second
  barrier), open:** the same routes as GLM's minor, plus an exported macro
  that calls a private factory. The specification's type ban
  (`disallowed-types` in `clippy.toml`, 5.11, point 3) is not built. See
  "Open items".
- **Minor (kind: contract wording), fixed (`4875117`):** the `PurgeFailed`
  documentation said the core acts on a report that names "a delivery it
  made". The specification says an open delivery, one not yet answered,
  and treats a repeat as ignored (5.10, point 6). `PurgeFailed` and `Ack`
  now say so, and say that only a demonstrated purge failure revokes.

## Security review

The class's security pass, run by hand with the security-review method on
`0f6b963..4bebd7f` (the merge of `m2a-71-types` is reviewed under its own
record). Seat: a Claude Code subagent, served model `claude-opus-5-5`,
read-only until its verdict. It is a Claude seat on Claude-written code,
so it counts as the class's security pass and not as a second family.

**Method.** Each area was read in the code and checked against the
contract specification at `m2a-67-spec`:

- capabilities: forgery, copying, widening, and confusion across
  bindings, contexts and generations;
- secrets: whether a nonce reaches `Debug`, `Display` or a log;
- untrusted values: whether every value a layer supplies is checked
  without a panic, `unwrap`, indexing or overflow;
- errors: whether any mapping turns a failure into success;
- the invalidation stream: lost or narrowed effects, and forged
  acknowledgements;
- the mint check: whether it holds beyond its recorded limits.

Each finding was confirmed in the code, and each fix was seen failing
first.

**Verdict: PASS, with one minor, fixed.** No blocker or major.

- **Capabilities.** Every field is private and set only through `Mint`.
  `HandleCap` is neither `Clone`, `Copy` nor `Default`, and neither
  capability implements `PartialEq`. Both `Debug` implementations leave
  out the nonce, as a test shows. A capability the core did not record is
  refused at run time (open item 3). Nothing found.
- **Untrusted values.** `Name::new` checks every cap before it allocates.
  `Extensions::push` uses checked addition and leaves the list unchanged
  on an error. Nothing in the crate indexes, unwraps or panics. Nothing
  found.
- **Errors.** `VfsError` has no success value. `surface` matches every
  value with no wildcard arm, and `Reserved::refusal` returns
  `NotSupported`. Nothing found.
- **Invalidation.** `Effects::merge` only widens: unequal entries become
  `All` and unequal rights become `All`. `covers` never lets a single name
  cover a rename. Whether a report is valid is the core's check (5.10,
  point 6), not this crate's. Nothing found.
- **Minor (kind: check bypass; the mint check read less than its
  documentation claimed), fixed.** Two routes let a crate outside the
  allow-list compile source the mint check never reads:
  - a symbolic link to a directory: `mod hidden;` reads
    `hidden/mod.rs` through the link, and the check skipped links whose
    names do not end in `.rs`;
  - a target whose root file is outside the package directory, such as
    `[lib] path = "../../elsewhere/lib.rs"`: the check walked only the
    package directory.

  Both were built and compiled with cargo outside the repository. The
  check now:
  - reports a link to a directory as unread;
  - refuses any target root that, once `..` and links are resolved, lies
    outside its package. Cargo reports the path as written, `..`
    included, so a plain prefix test passed the planted case; the case
    failed until the path was resolved.

  Evidence: a planted case in `check-deps --self-test`, and a unit test
  (`scan_reports_a_directory_link_and_a_target_outside_the_package`).
  It is rated minor, not major: no capability can be forged through it,
  because the core's record check is the trust boundary. It is the same
  kind of route as DeepSeek's round 2 major, though, and DeepSeek rated
  that one major.
- **A further limit, recorded and not fixed:** a build script can write
  Rust source into its own package before the compiler reads it. The
  check reads the tree as it stands when the check runs. The type and
  method ban of open item 2 closes this, as clippy reads what the compiler
  reads. The module documentation now lists it with the other limits.
- **The open items.** None is worse than stated. The routes of open item
  1, and the build-script route above, all give a layer a mint value or a
  capability built outside the core's record. The core refuses that
  capability at run time (5.3, point 3). Open item 3, the core's run-time
  record check, therefore stays the barrier on which the security of the
  contract rests.

## Open items

1. **An allowed crate handing `Mint` out without spelling it:**
   - a private alias in a public signature;
   - a default type parameter;
   - an `include!` in an allowed crate;
   - an exported macro calling a private factory;
   - a trait's items, a trait implementation, or an enum variant.

   Review holds these until item 2 lands. The runtime barrier, the core's
   check of every capability against its own record, is unaffected.
2. **The second barrier of the contract specification, 5.11, point 3.**
   Closed by:
   - `ironafs_vfs::Mint` under `disallowed-types` in `clippy.toml`;
   - `Mint::new`, `Mint::caller` and `Mint::handle` under
     `disallowed-methods`, since a type ban sees only types written out,
     while clippy resolves a call however its receiver was reached;
   - named `#[expect]`s in the allowed crates;
   - the mint check refusing an `allow` or `expect` of either lint outside
     them;
   - planted cases for each.

   It closes item 1.
3. The core's run-time record check (C8, point 2), owed by the brief that
   mints capabilities and by the scripted core (#98).
4. The name codec's fuzz target `ironafs-vfs_name_linux`, which lands with
   #45.
5. `/security-review` for this change, which class S requires: done,
   see "Security review".
