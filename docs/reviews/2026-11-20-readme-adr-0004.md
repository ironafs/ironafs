# Review record: the README follows ADR 0004

## The change

Class P.

- **Goals:** the first goal is now "Do what users of an AFS client rely
  on", and it points to ADR 0004 for where IronAFS will differ. It used to
  promise parity with another client, which ADR 0004's decisions
  contradict (no PAGs, no set-uid privileges).
- **Why:**
  - each platform's claim is backed by the
    [kernel code research note](../research/2026-11-20-kernel-code-and-user-space.md);
  - on Linux, the README says IronAFS expects metadata-heavy work to be
    slower, until measured.
- **New:**
  - the planned platforms (ADR 0004, L37 to L39);
  - the order of work (O50).
- **Building:** the hook and individual-check detail now lives only in
  `CONTRIBUTING.md`.
- **The research note:** long lines wrapped; it says no timed workloads
  are named yet; and the Linux 6.9 date for FUSE passthrough cites Kernel
  Newbies.
- **Written by** `claude-code:claude-opus-5-5`, after an independent
  read-only review by Claude Mythos 5.2 (same family, not a required
  seat) that proposed most of the changes.

## Findings

- **Majors, fixed:**
  - **`\\afs` was presented as the path for every user.** L15 uses it
    where the name can be used, and the loopback address otherwise.
  - **The tier 1 Ubuntu row** left out that it covers the kernels of
    GitHub's hosted runners. Generic kernels are candidates (L37).
  - **The Windows rows** left out workgroup use, and Windows 10's
    Extended Security Updates and current-update conditions (L37, L38).
- **Minors, fixed:**
  - "Slower" now says what it is measured against.
  - Windows signing has exceptions. The cross-signed trust removal is
    named by release, with Microsoft's allow list.
  - Set-uid wording now says what L3 decides: no privilege is gained.
  - The candidates are listed exactly as L37 and L39 name them.

The review stopped there: no blocker or major finding remains.
