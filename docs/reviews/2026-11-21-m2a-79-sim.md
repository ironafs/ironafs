# Review record: the simulator, part (a): the baton scheduler, trace, replay and witness

## The change

Class I. Issue #79 (plan id M2a-37), its pull request (a). Parts (b),
the network and clock models, and (c), the disk, crash points and the
`xtask sim` commands, follow. The contract is the seams and scheduling
specification (`docs/specs/seams-and-scheduling.md`, issue #71).

- `ironafs-sim`, a new test-only crate. It has:
  - the baton scheduler of the specification's 5.6;
  - streams seeded from (seed, label, incarnation);
  - a fixed trace encoding with a closed error vocabulary;
  - strict replay;
  - a child process and a supervisor with an outer limit;
  - two-process determinism;
  - golden traces, committed as exact bytes;
  - the interleaving witness;
  - the re-measured share of segregated schedules (54 of 2048 seeds).
- `check-deps` gives `ironafs-sim` an empty third-party list, so no async
  runtime enters it.
- The `Rpc` and `Disk` seam types do not exist yet. #71 owns them, and
  they are being built as its part 2. So the sample operation is the
  minimal scripted operation of the specification's section 13, Q11. It
  reads the real `Clock` and `Rng`, and yields at the simulator's own
  reply-slot and deadline waits. Parts (b) and (c) move it onto the seam
  types.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## Findings

GLM, round 1:

- **Minor, fixed (`220f779`):** no test exercised the watchdog (the
  specification's 10.5, point 7, a planted real sleep). A unit test now
  sleeps a task past a 50 ms watchdog and asserts the unconfirmed lost
  baton. It was shown red against a watchdog whose timeout check was
  disabled, and against one whose wait predicate was inverted. The sleep
  is behind `cfg(test)`, not a Cargo feature, a named departure: a feature
  that is off by default would leave the test unrun by the workspace
  command.
- **Minor, fixed (`220f779`):** a failed spawn at a task's first grant,
  on the grant-before-spawn path, left the baton held. The run therefore
  waited out the watchdog and was reported as a lost baton. The holder is
  now cleared, and the run fails as a host failure. A new plant,
  `fail_spawn`, drives the test, which failed first with `LostBaton`.

Of GLM's eight uncertain items:

- One led to a fix (`fa4299b`). A replay that differs only in its
  terminal line kept the check's failure class, not `Diverged`, because a
  run keeps its first failure. The replay's divergence is now kept apart
  and wins. Its test failed first. This was not a false pass: the bytes
  differed, and the exit was a failure.
- A small one was fixed with the minors (`220f779`): a kill that races
  the child's own exit no longer turns an over-limit child into an I/O
  error.
- The rest were answered:
  - which pieces later parts carry;
  - the coverage of teardown;
  - the fixture targets against CI's runners;
  - the watchdog's headroom;
  - the generator's value-stability;
  - the runs, which the evidence below covers.

`2dada24` names a clippy expectation on the plants struct. No behaviour
changed.
