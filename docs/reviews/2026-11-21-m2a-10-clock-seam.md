# Review record: the clock and randomness seam

## The change

Class S. Issue #58 (plan id M2a-10).

- A new pure crate, `crates/ironafs-time` (`no_std` with `alloc`, no
  dependencies): the `Clock` interface with its three clocks (boot, awake,
  wall; ADR 0004, C37, point 1) and the `Rng` interface (C3, point 3),
  both fallible; boot and awake instants and deadlines in unsigned 64-bit
  nanoseconds, one generic type per role with a clock marker, so a
  deadline cannot be checked against the other clock; wall time as signed
  64-bit seconds since 1970 with a nanosecond part (C38, point 1). All
  arithmetic is checked.
- In `crates/ironafs-test-support`: `SeededClock` (three virtual clocks
  that move only when the test moves them, suspend, wall jumps, failing
  reads) and `SeededRng` (the SplitMix64 byte stream, failure on demand),
  and a test that one seed reproduces the same sequence.
- Coding standards rule 7's bans in `clippy.toml`: `Instant::now` and
  `elapsed`, `SystemTime::now` and `elapsed` as disallowed methods;
  `RandomState`, `HashMap`, `HashSet` and `Command` as disallowed types.
  `cargo xtask check-bans` lints a fixture of planted calls with the
  repository's `clippy.toml` and fails unless every ban fires and none is
  unresolved; `--self-test` proves a removed method ban, a removed type
  ban and a misspelt ban are caught. It runs in `cargo xtask check` and
  the CI lint job.
- Two named exceptions, each stated in the code: the property runner's
  shrink time limit reads the real clock (rule 7 covers the code under
  test, not the test runner), and xtask, which is never shipped, runs its
  tools through one `Command` alias exempt from the type bans.
- Not in this change: the production clocks (in `ironafs-os`) and the
  production random source (behind `ironafs-crypto`), and the waiting
  operation, signals and doubt count the seams specification proposes,
  which is not accepted yet.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## Findings

GPT, round 1:

- **Major (origin: GPT round 1; kind: incomplete ban), fixed
  (`a18875e`):** the bans left host time and entropy reachable in std
  crates: `RandomState::default()`, `HashMap::new()` and a subprocess
  such as `date` drew no warning. A clippy probe showed no method path
  names `RandomState::default` or the hasher a map gets from `default`,
  `from` or `collect`. So `RandomState`, `HashMap`, `HashSet` and
  `Command` are now disallowed types, each with planted cases, and the
  self-test gained a removed type ban.
- **Major (origin: GPT round 1; kind: contract wording), fixed
  (`67a3d70`):** the `Clock` documentation expired only the deadlines on
  the clock whose read failed, and let a successful read reopen deadline
  creation. It now quotes C37, points 4 and 5: any failed read expires
  every outstanding deadline and makes callbacks suspect, and no new
  deadline is set until a valid sample returns. It also says nothing in
  the crate enforces this; the code that holds the clock does. No code
  change was needed: the crate keeps no state that could reopen deadline
  creation.
- **Minor (origin: GPT round 1; kind: duplicated code), fixed
  (`b43457a`):** `check-bans` copied the fixture writer. It now uses
  `fixture::write_file`.

Implementer, after round 1:

- **Defect (origin: implementer, `cargo xtask check`; kind: dependency
  policy), fixed (`3b77d29`):** `cargo deny` read the new workspace path
  dependency on `ironafs-time`, which had no version, as a wildcard,
  which `deny.toml` refuses. It now states the exact version. GLM and GPT
  verified this commit in round 2.

GPT, round 2:

- **Minor (origin: GPT round 2; kind: over-broad exemption), fixed
  (`f29a5ca`):** a crate-wide expect for subprocesses also silenced the
  `HashMap`, `HashSet` and `RandomState` bans across xtask. xtask now
  names subprocesses through one crate-private `Command` alias that
  carries an item-level expect. A `HashMap` planted in xtask is flagged
  again.
- **Minor (origin: GPT round 2; kind: test coverage), fixed
  (`f29a5ca`):** the fixture did not plant the exact `HashMap::new()`
  expression, and planted `RandomState`'s default only through a banned
  return type. Both expressions are now planted in functions whose
  signatures name no banned type.

GPT also recorded these as uncertain, not as findings: its sandbox could
not run nextest, clippy or the self-tests; whether protocol expiry needs
its own wall-clock deadline type is left open (C37 puts server-granted
deadlines on the boot clock).
