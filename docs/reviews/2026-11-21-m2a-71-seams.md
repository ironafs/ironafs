# Review record: the `Rpc` and `Disk` seams and the scheduling model

## The change

Class S. Issue #71 (plan id M2a-70).

- `docs/specs/seams-and-scheduling.md`: the design page that settles,
  before operation code is written against them, the `Rpc` and `Disk`
  interfaces of ADR 0004 C3, point 3 (crates, shapes, error sets,
  deadlines); `Clock::sample` and `Clock::wait` as the one blocking
  primitive, with the doubt latch and the episode counts of C37; the call
  owner, its decision guard, the per-connection send lock and the close
  fence; the baton scheduling model under the simulator, replay and trace
  rules; the two ends of a run for the simulated disk and its persistence
  model; the driver crates for real RPC and file I/O; the pure-crate rule;
  and the conformance obligations.
- `docs/specs/README.md`: the page's index row.
- **Written by** `claude-code:claude-opus-5-5` (drafting, and the fixes
  of every round).
- The branch is stacked on #85 (`docs/specs/`, its README, template and
  the XDR profile) and merged `main` once (`6e35473`), so that ADR 0005
  and the amended C4 trigger the page quotes are in its tree.

## Findings

Origin tags: **[draft]** pre-existing in `ea3c8fe`; **[fix N]** introduced
by fix round N. Kinds as the workflow names them.

### Round 1, DeepSeek (all addressed in `031f1a4`)

- **Blocker, [draft], consistency between parts, fixed.** `Rpc` sat in
  pure `ironafs-rx` but took `&Cancel` from the standard-library crate
  `ironafs-sync`, which a `no_std` pure crate cannot name (the same defect
  as GLM's major). `Rpc::call` and `accept` now take a `WatchRef`, a shared
  handle on the `Watch` trait in pure `ironafs-time`, as `Clock::wait`
  already did; the concrete `Cancel` stays in `ironafs-sync` and hands one
  out (5.2, point 1; 5.3, point 5).
- **Major, [draft], missing mechanism, fixed.** `Clock` had no sample
  carrying the doubt counts, so no deadline could latch them. `Clock`
  gains `sample`, returning a `Stamp` with the doubt and episode counts,
  and deadlines are built from stamps (5.3, points 1 and 2).
- **Major, [draft], contract, fixed.** C37, point 4's wall-time jump was
  missing. `Stamp` carries wall time and an episode count, and a wall jump
  is an episode that moves no doubt count (5.3, point 2).
- **Major, [draft], correctness, fixed.** The state directory's parent was
  to be synced through `Disk`, whose root-relative paths cannot name it.
  The parent sync moves to driver construction, and durable records go
  only in the root or a directory created and synced in this incarnation
  (5.5, point 6; open question Q18).
- **Major, [draft], correctness, fixed.** A closed connection was not in
  the owner's arbitration. Each submission carries its connection's fence
  and the shutdown fence, `close` fires the fence before it returns, and
  the arbitration checks it (5.4, point 4). Round 2 found the ordering
  argument incomplete (below).
- **Major, [draft], missing mechanism, fixed.** `Disk` had no directory
  removal for the incarnation sweep. `remove_dir`, `EntryKind`, `IsDir`
  and `NotEmpty` added (5.5, points 1 and 9).
- **Major, [draft], other (a test that could not fail), fixed.** No `Disk`
  case read strictly inside a file for C46, point 4. `part_inside_is_exact`
  added (10.5, point 1; section 9).
- **Minors, [draft], fixed:** decisions the page keeps are now quoted and
  each has a section 9 row, and the rest are named as context (completed
  after round 2); every working decision's trigger is copied (section 11);
  source rows match their uses; the unlabelled Rust facts are labelled
  UNVERIFIED with Q16; any read error on a clean chunk is a miss, with a
  test; `Disk`'s conformance list names every call's errors; a send error
  that a retry cannot clear settles `NotSent(Unreachable)`;
  `NoReply(ReplyTooLarge)` is never read as a timeout; the conformance
  implementations are named per seam; every open question names its
  issue.

### Round 2, DeepSeek (fixed in `52c3084`)

- **Blocker, [fix 1], correctness, fixed.** The close fence promised that
  no packet is accepted after `close` returns, but `close` could fire the
  fence between the owner's arbitration and its send. Each connection now
  has a send lock: every datagram is handed inside a hold of it after
  reading the fences unfired, and `close` fires the fence inside a hold of
  the same lock, so the two exclude one another (5.4, points 4 and 5). The
  test's expected order was corrected.
- **Major, [fix 1], correctness, fixed.** `Deadline`'s variants were
  public, so a deadline could be built or rebuilt with any latch. It is
  now opaque, with a compile-fail doc-test (5.3, point 1). Round 3 found
  the constructors' sampling broke the pure-crate rule (below).
- **Minor, [fix 1], contract, fixed.** Section 1 still said the context
  decisions were ones the page "must keep word for word". Reworded.
- **Minor, [fix 1], other, fixed by the merge of `main`.** The ADR 0005
  link did not resolve on the branch.

### Round 2, GLM

- **Minor, [fix 1], other, fixed by the merge of `main` (`6e35473`).** The
  quoted C4 trigger and the ADR 0005 link did not match the branch's tree.

### Round 3, DeepSeek (fixed in `e4e007a`)

- **Major, [fix 2], consistency between parts, fixed.** The `Deadline`
  constructors in pure `ironafs-time` called `clock.sample()`, against
  5.2, point 5 ("pure crates call no seam"). The constructors now take
  the caller's fresh sample as `now` and call no seam; a call-site check
  confines them to one sampling function per crate (5.3, point 2).
- **Minor, [fix 2], contract, fixed.** "A stale stamp cannot lower the
  latch" said the opposite of the rule. It now says a stale stamp cannot
  hide a failure, and the test is renamed.
- **Minor, [fix 2], contract, fixed.** The close fence claimed N7, point
  5 outright. The page now reads point 5's "leaves" as the transport's
  acceptance, where the simulator's check observes it, and says the wire
  is not controlled (5.4, point 4).

### Round 4, DeepSeek (fixed in `28bbcbc`)

- **Major, [fix 3], correctness, fixed.** The latch used `from`'s count
  while the text said `from` gave only the instant, and nothing
  constrained `from`.
  - **The controller's first direction, refuted.** The controller first
    directed latching on `now`'s count alone, so that `from` gives only
    the instant. The fixer refuted it, and the controller agreed. The
    deadline's instant is `from`'s plus `d`. After a boot-clock regression
    of R between the arrival and `now`, that instant is on the timeline
    before the regression and is read on the clock after it, so a latch
    from `now` alone would leave the deadline up to R later than `d`
    after the arrival, with R unbounded. That breaks C37, point 4 ("A
    regression of a monotonic clock, or a failed sample, also treats
    every boot-clock deadline ... as possibly expired"): the constructors
    are general, and a callback lifetime counted from `first_sent` would
    lengthen by R, against 5.4, point 4's "can only be shorter or fail,
    never longer". It breaks C39, point 3's "a deadline counted from
    arrival". The lower-of-two latch is what fails such a deadline. The
    direction held only for a failed read with no regression, and would
    not have closed the finding: ignoring `from`'s count hides a failure
    after a true arrival even for a genuine `from`.
  - **The fix (the controller's second direction).** The latch stays the
    lower of the two counts, and the page states why `from`'s count is
    needed. The constructors refuse a `from` newer than `now` on the
    deadline's clock (`FromAfterNow`, a pure value check), which the
    caller treats as `ClockFailed`. The call-site check also pins `from`
    to the request's recorded arrival or a reply's `first_sent`. Tests
    for a regression between `from` and `now` and for a refused `from`.
- **Minor, [fix 3], contract, fixed.** The page credited the lint's
  disallowed-paths list with a rule it cannot express. It now states
  `seams::deadline_built_from_a_fresh_sample`'s exact rule (one named
  sampling function per crate, direct calls only, one `let`-bound
  `sample()` passed as `now`, the allowance on that function only), calls
  the list a second net, adds plants for a second allowed function, a
  module-level allowance, a closure and a function pointer, and names
  macros as a limit that review covers.

### Round 5, DeepSeek (PASS; minors fixed in `d936751`)

- **Minor, [fix 4], contract, fixed.** A forged `from` with a count equal
  to `now`'s and an instant not later is not refused, and the page's
  closing "at worst" claim understated it. The page now states that
  residual, that only the call-site check bounds it, and records it as a
  limit with plants that are expected to pass.
- **Minor, [fix 4], contract, fixed.** The `first_sent` route had no
  stated limit. The page now says the check trusts that only the call
  owner writes a `Reply`'s `first_sent`, once, from its hand-off's `pre`
  sample, and that review covers who builds a `Reply`.
- **Minor, [fix 4], contract, fixed.** The guarantee holds only inside
  the workspace. The page now says so: every crate is unpublished
  (`publish = false`), and Rust has no visibility that would let the
  sampling functions in other crates call the constructors while keeping
  them from everyone else.
