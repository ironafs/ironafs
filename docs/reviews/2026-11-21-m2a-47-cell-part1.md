# Review record: `cargo xtask cell`, the pinned definition, the engine runner, teardown and the verified install

## The change

Class I. Issue #47 (the test cell fixture), its first part: tasks 1 to 4
of its plan. Bringing the cell up, its readiness check, `cell up` and
`cell down`, and the CI job come after the hosted-runner spike.

- `crates/xtask/cell/pins.txt`: the one pinned definition. It holds the
  base image by digest (the multi-platform index and each platform's
  manifest), a dated snapshot of the Debian archive, the synthetic cell
  and realm names under `.invalid`, and each package of the closure at
  an exact version with its SHA-256. The parser refuses a floating
  version, a short digest, credentials or a query in a URL, an option
  that weakens apt's checks, a missing architecture, a required package
  at another version, and a name outside `.invalid`. It lists every
  error, not only the first.
- The engine runner: Docker or Podman, chosen by `PATH` or
  `IRONAFS_CELL_ENGINE`. Every step runs with an empty `DOCKER_CONFIG`, a
  `{}` `REGISTRY_AUTH_FILE` and no `DOCKER_AUTH_CONFIG`, so every pull is
  anonymous. A secret step's output is never reported.
- The run directory, private to its owner on Unix, and the state file:
  each engine object is recorded before it is created. Teardown removes
  everything recorded, and treats an object already gone as removed.
- The verified install. The snapshot is the builder's only apt source,
  checked against the image's archive keyring, and any apt warning is
  refused. Each package's SHA-256 is compared with its pin before `dpkg`
  runs. The installed versions are compared with the pins before the
  image is committed.
- `cargo xtask cell pin` resolves the closure for each architecture and
  rewrites the pin file's package lines. The same inputs give the same
  bytes.
- Containers are not started in this part. The tests drive a fake
  runner.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first), fixes included.

The implementer named six departures:

- **Run ids:** `<pid in hexadecimal>-<n>`, taking the first unused `n`.
  An id is unique on one target directory while earlier runs' directories
  remain, and teardown keeps a directory whenever objects remain.
- **Teardown keeps leftovers:** the plan has teardown delete the run
  directory. When a removal fails, teardown instead removes the keys,
  rewrites the state file to record what remains, and keeps the
  directory, so a later teardown can try again.
- **The `pin` signature:** the plan's `pin(run, def) -> String` became
  `pin(run, def, dir, state) -> Vec<PackagePin>` plus a separate
  `render`. The caller owns the run directory and the teardown, and
  rendering is tested without a runner.
- **`remove_dir`:** a copy of `fixture::remove_dir` with the cell's error
  type. GLM's seventh finding; replaced by a shared helper (below).
- **Fixtures from memory of apt's output:** the `apt-get --print-uris`,
  `dpkg-query` and `apt-get update` fixtures were written from apt's
  documented output formats, not captured from a run. The first real
  `cell pin` on the hosted runner checks them.
- **`dead_code` expectations:** the install module, the network object,
  and `RunDir::latest`, `State::load` and `down` are not called yet
  outside tests. Each carries `expect(dead_code)` with a `TODO(#47)`
  reason, which fails the build once the code is used.

## Findings

GLM, round 1. All seven are fixed in `a75ce64`, after `origin/main` was
merged in `b72c640`. Where behaviour changed, a new test was seen
failing first.

1. **Minor, fixed:** the base image `prepare` pulls was never recorded,
   so it survived every teardown, and nothing could later attribute it.
   It is now recorded before the pull, so teardown removes it (`rmi` by
   digest) even after a pull that failed or was interrupted. A base image
   cached before the run is removed too, which costs a pull next time.
   Test: `prepare_records_the_base_image_before_pulling`; the install
   test's expected state file now starts with the base image.
2. **Minor, fixed:** when writing a step's input failed (a broken pipe
   from a child that exited early), the runner returned only the write
   error, and the engine's own diagnostic was lost. The child's status
   and output are now kept. The step fails, even with exit status 0, and
   the write failure follows the engine's error output. Tests:
   `failed_input_write_keeps_the_childs_status_and_output`,
   `failed_input_write_fails_a_step_that_exited_zero`.
3. **Minor, fixed:** a replaced file was staged under a fixed name
   (`latest.new`, `state.new`), so two runs in one target directory
   shared it. The staged name is now unique to the process and the call:
   `.ironafs-<name>-<pid>-<n>`, created with `create_new`. Test:
   `run_dir_create_ignores_another_runs_staging_file`.
4. **Minor, fixed:** a failed teardown told the operator to run
   `cargo xtask cell down`, which does not exist yet. The message now
   says that what was not removed stays recorded in the run directory.
   Test: `teardown_failure_names_no_command_that_does_not_exist`.
5. **Minor, fixed:** when the latest-run marker could not be written,
   the new run directory was left behind. It is now removed, and a
   failure to remove it is reported with the first. Test:
   `run_dir_create_removes_its_directory_when_the_marker_fails`.
6. **Minor, fixed by documentation:** the image's index digest was
   parsed but never used. The plan keeps it: the definition's type
   carries it, the run summary of a later part writes it, and pulls use
   the platform digests and never fall back to the index. The field and
   the pin file's header now say what it records, with a `TODO(#47)` for
   the summary. No behaviour changed, so no new test.
7. **Minor, fixed:** `state::remove_dir` copied `fixture::remove_dir`,
   and the staged write was a near-copy of the hooks' staging. Both are
   now in one module, `crates/xtask/src/files.rs`, that takes the
   caller's error mapping. `fixture`, `hooks` and the cell use it, with
   unit tests of its own. This is a named departure from "generalise in
   place": three modules share the helpers. The hooks' staging errors now
   read "create temporary file" and so on, instead of "temporary hook";
   no test or caller depends on the wording.

GLM also listed what it could not check:

- whether the committed closure is really what apt resolves in the
  pinned image. The `print-uris` fixtures mirror the pin file, so the
  round trip proves the plumbing, not realism. A stock image without the
  Kerberos libraries would give a larger closure, and a real install
  would then fail closed at `dpkg`. The first real `cell pin` settles it;
- the engines' own credential fallbacks (Podman's runtime `auth.json`,
  Docker's legacy `~/.dockercfg`, registry mirrors in the system's
  configuration). The isolation is verified in code and by a unit test
  on the child's environment, not by running an engine;
- the engines' wording for an object already gone. If an engine words it
  differently, teardown reports a spurious failure, never a silent leak;
- whether `apt-get install --print-uris -qq` can print a non-URI line
  with exit status 0. If it can, `cell pin` fails closed;
- `percent_decode` accepts `%+X`, because the standard integer parser
  admits a sign, although its documentation says a malformed escape is
  refused. GLM traced no reachable failure: the rendered pin file is
  parsed again, which refuses such bytes. Not changed in this round;
- seven planted pin fixtures and the arm64 `print-uris` fixture, which
  its read-only tools did not print. The tests that read them assert
  their exact outcomes.

The review stopped there, under the stop rule: only minor findings,
fixed and recorded, so no verification round.
