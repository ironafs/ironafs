# Review record: the test inventory ratchet

## The change

Class I. Issue #72 (plan id M2a-77), from the test strategy
(`docs/specs/testing.md`, 5.4, point 5).

- `cargo xtask inventory` lists the workspace's tests with nextest's
  machine-readable list, runs them once (`--profile ci --retries 0
  --no-tests fail --no-fail-fast`) and reads how each ended from that
  run's JUnit report, removed first so only this run's report is read.
- `tests/inventory/<crate>.txt` holds one sorted line per test, keyed by
  test binary, name, target and feature set, with an optional
  `quarantined=#<issue>` mark. A test in the run without a line fails; a
  listed test that did not run and pass fails, unless it is marked
  quarantined and nextest still lists it.
- Against the base revision's inventory: a removed entry needs a line
  that the change adds to `tests/inventory/removed.txt`; the base's lines
  stay; a quarantine mark stays until the test passes again; a mark
  without an issue fails.
- Exit status 0, 1 for violations, 2 when the check could not run or
  compared nothing. `cargo xtask inventory update` adds lines and never
  removes one. `--self-test` runs real nextest on a fixture workspace and
  plants each failure case in a git repository of the fixture.
- CI's test job runs the check against the merge commit's first parent,
  and its self-test, with `contents: read` only; `cargo xtask check` runs
  both.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent).

## Findings

GLM, round 1, all fixed in `f5558c2`. Each fix has a unit test seen
failing before the fix and a `--self-test` case; with each fix reverted
by hand, both failed (EXECUTED by the implementer, 2026-11-21).

- **Major:** a quarantined entry was exempt from every existence check:
  a marked line whose test was deleted passed as "skipped". A marked
  entry that nextest no longer lists now fails; nextest lists ignored and
  filtered tests, so a quarantined test that still exists is listed.
- **Minor:** a line tagged for a target that no CI job runs was never
  reconciled. A `target=` tag may now name only a target a CI job
  reconciles (x86_64 Linux today); the change that adds a CI job for
  another target adds it to that list. Untagged lines apply to every
  target and are all reconciled by the Linux job.
- **Minor:** the removal record was keyed by name only, so an old line
  excused a later removal of a re-created test. Only a line the change
  adds now records a removal it makes.

The round's six uncertain items were answered in the fix round: what was
executed (nextest's list and report on 0.9.143, the reconciliation of
the 263 checked-in lines, the omitted feature-gated binary) and what
waits for CI. Two format failures were added to the self-test, which the
round noted were planted only in unit tests.
