# Review record: `check-pure`'s exact matrix and the crate root's form

## The change

Class I. Issue #46 (plan id M2a-13), the parts the first change
(`a35ba20`, recorded in
[2026-11-21-m2a-13-check-deps](2026-11-21-m2a-13-check-deps.md)) left out.

- `cargo xtask check-pure` records the (crate, target, profile) triples
  the compiler built, from cargo's artifact messages and the compiler's
  dependency-info file beside each library's metadata, which must list the
  library root. The run passes only if that set equals the expected one:
  every pure crate present, every target of `rust-toolchain.toml`, dev and
  release. A passing run prints the matrix and the pure crates of ADR 0004,
  C4, point 1 not yet in the workspace.
- The library root must carry an unconditional, top-level
  `extern crate alloc;`, and may hold no crate-level `#![cfg(...)]`, also
  inside a `cfg_attr`.
- A pure crate may not name `arch`. `core::arch` holds safe functions such
  as `__cpuid`, whose result depends on the machine; neither the core-only
  build nor `-F unsafe_code` stops them. This is a token rule, not the
  clippy `disallowed-methods` ban the issue names, for two reasons measured
  with the pinned toolchain (1.100.0): on an aarch64 host the x86_64 path
  does not resolve, and clippy only warns ("does not refer to a reachable
  function") and bans nothing; and a `clippy.toml` in a crate's directory
  replaces the root file whole, so a crate could drop the ban. Also
  measured: a module path under `disallowed-types` bans nothing and exits
  0, but does warn ("expected a type, found a module").
- The self-test adds cases for a root without `extern crate alloc;`,
  `#![no_std]` after an item, `#![cfg_attr(not(test), no_std)]`, a
  crate-level cfg and `__cpuid` behind a `target_arch` cfg; negative
  controls that skip a pure crate, a target or a profile, build an extra
  crate, or remove a dependency-info file; and a fixture that adds
  `ironafs-rxkad`, checked with no change to the check.
- The clock and randomness bans of coding standards rule 7 are kept by
  `check-bans` (issue #58, landed as `39c853e`), not here.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent).
