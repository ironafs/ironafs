# Review record: the scripted core, part 1

## The change

Class I. Part of issue #98 (plan id M2a-72). Based on the branch of
`ironafs-vfs` part 1 (#67), at `1c2d2bb`.

- `ScriptedCore` in `crates/ironafs-test-support`, a dev-only crate: a
  core behind the `ironafs-vfs` contract whose state a test scripts, so a
  layer is tested without the client chain (ADR 0004, C7). It holds:
  - the capability table: caller and handle capabilities minted through
    `Mint` with seeded nonces, and every capability handed back checked
    against the core's own record for the presenting binding (C8,
    point 2; C13; the contract specification, 5.3);
  - each binding's invalidation stream: one slot per held node, each
    effect with its merge revision, at most one delivery unanswered per
    slot, an overflow past the byte bound that stays open until
    acknowledged, and the validity rule for acknowledgements and failure
    reports (C17; 5.10);
  - weak and authoritative breaks (C24) and the injected purge failure,
    which stales one node in every binding, revokes every context's
    handles on it and offers the purge again (C15, point 6; 5.10,
    point 5);
  - layer faults, counted per binding (7, point 3).
- `PurgeFailed` is defined in `ironafs-test-support` until `ironafs-vfs`
  has it (`TODO(#67)`).
- `ironafs-vfs` joins `[workspace.dependencies]`.
- Not in this change: what waits on the contract's operations and request
  and completion interfaces (bytes served per context, the set-uid file and
  the device entry, a reply whose state changes before submission, and the
  contract tests shared with the real core). See "Limits".
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

## Findings

### Round 1, GLM

- **Major (kind: refusal values diverge from the contract), fixed
  (`8da7f30`):** a capability with no record or recorded for another
  binding was refused with `Access`, where 5.3, point 3, says `Stale`.
  Every capability refusal is now `Stale`, and a capability presented on a
  binding other than its own is also counted as a layer fault.
- **Major (kind: lost event), fixed (`8da7f30`, reworked in `0eb82fe` and
  `5ce1fdb`):** the purge offered again after `purge_failed` could be
  erased when its slot folded into an overflow, leaving the node stale with
  nothing left to acknowledge. A re-offer that folds now travels in the
  overflow, and the node's staleness ends with the acknowledgement of the
  delivery that carries it.
- **Minor (kind: vacuous test), fixed (`8da7f30`):** the release test
  probed with nonce 0, so it passed with release a no-op. It now probes
  with the real nonce, which passes before release and is refused after.
- **Minor (kind: guard weaker than its documentation), fixed (`8da7f30`,
  then aligned in `5ce1fdb`):** an acknowledgement of revision 0 was
  accepted. Acknowledgements have no reply in the contract, so it is now
  classed by 5.10, point 6: a repeat when a delivery for that node or
  overflow exists, otherwise a fault.
- **Minor (kind: default diverges from the contract), fixed (`8da7f30`):**
  the default byte bound was 64 KiB. It is now the contract's proposed
  1 MiB per binding (5.10, point 9).

### Round 2, GLM

- **Major (kind: failure report dropped), fixed (`5ce1fdb`):** a
  `PurgeFailed::Node` naming a delivery whose slot had folded into an
  overflow was classed a repeat and ignored, so a demonstrated purge
  failure revoked nothing. Each node's unanswered delivery is now kept
  apart from its slot, and survives a fold, so the report is valid and C15,
  point 6, applies.
- **Minor (kind: release fault rule), settled by the specification:**
  releasing a handle recorded for the binding but no longer live was not
  counted as a fault. 5.6, point 2, at `5ba3297` states exactly that rule:
  only a capability with no record for the binding is a fault.
- **Minor (kind: revision 0 classed against the text), fixed (`5ce1fdb`):**
  revision 0 was always a fault. It now follows 5.10, point 6: a repeat
  when at or below a delivery made, a fault when none was.
- **Minor (kind: stale state ended early), fixed (`5ce1fdb`):** a later
  node delivery that did not carry the re-offer ended the node's
  staleness. The re-offer's place (the node's slot, the next overflow, the
  open overflow) is now tracked, and only the delivery that carries it
  ends the staleness.
- **Minor (kind: fault counts not per binding), fixed (`5ce1fdb`):** one
  count served the whole core. `layer_faults(binding)` now counts per
  binding (7, point 3).

### Round 3, GLM

- **Minor (kind: diverges from the contract), fixed (`fe66f34`, not
  re-reviewed):** an unscripted uid was refused with `Access` on every
  binding, while 5.3, point 1, says a shared binding finds or creates the
  uid's context. Every binding of the scripted core is shared, so an
  unscripted uid now gets a context the core creates, the same one on
  every later call. An unscripted SMB session is still refused with
  `Access` and counted as a fault.
- **Minor (kind: not modelled), recorded as a limit:** the event deadline
  of 5.10, point 8 (silence treated as a failed purge) needs a clock, and
  the scripted stream has none. See "Limits".

## Alignment with the contract specification

At `5ba3297`, the scripted core follows:

- 5.3, points 1 and 3: refusals with `Stale`; an unaccepted attestation
  with `Access`; another binding's capability and an unknown SMB session
  counted as faults;
- 5.6, point 2: release never fails; a capability with no record for the
  binding is a fault; a dead handle's release is not;
- 5.10, points 1, 3, 5, 6 and 9: per-effect merge revisions, one
  unanswered delivery per slot, an overflow open until acknowledged,
  `PurgeFailed` in its two forms, the valid, repeat and fault classes, and
  the 1 MiB bound;
- 7, point 3: faults counted per binding.

## Limits

- **No clock.** An event a binding neither acknowledges nor reports stays
  open, where the contract treats it as a failed purge at its deadline
  (5.10, point 8). That path needs the request table's deadline (5.8,
  point 3); it comes with it, on `ironafs-test-support`'s seeded clock.
- **Shared bindings only.** Per-user bindings and their owner check (5.3,
  point 6) are not modelled.
- **No suspension.** A handle is live, revoked, of a retired generation or
  on a detached binding; C14's suspended state is not modelled.
- **No operations.** The contract's operations and request and completion
  interfaces are not in `ironafs-vfs` yet, so the scripted core has no
  read, lookup or reply path; `open_handle` stands in for open. The parts
  of #98 that need them wait on the contract specification and #67's next
  part.
- **Faults are counted, not logged** (7, point 3, also logs them once per
  episode).
