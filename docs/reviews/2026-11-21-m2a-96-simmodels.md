# Review record: the simulator's VL and fileserver models, part 1: the read side

## The change

Class I. Issue #96 (plan id M2a-38), its first pull request. The contract
is the specification of volume location and file-service reads
(`docs/specs/vl-fs-read.md`, issue #65). The callback specification
(`docs/specs/callbacks.md`, issue #66) was read for the promise and break
rules. The models are written from those specifications and nothing else
(ADR 0001). This pull request is based on the simulator's part (a)
(#79).

- In `ironafs-sim`, a `model` module:
  - a VL model: the two lookups and the address list;
  - a fileserver model: status, bulk and inline bulk status, the 32- and
    64-bit fetches and volume status;
  - the abort codes of the specification's 5.9;
  - per-procedure refusals that drive the fallback catalogue (5.8);
  - planted bulk faults (5.4, point 10);
  - busy spells;
  - callback promises recorded per client;
  - a second client's write that bumps the data version and records the
    breaks it owes;
  - a cell that routes requests by address and service, drops what a
    down or absent server would never answer, and moves a volume.
- File bytes are computed from the file id and the offset, with writes
  laid over them. So files of 4 GiB and more are served at any offset
  without memory.
- The scheduler adds one capability: a server model may drop a call, whose
  caller then waits until its deadline. The trace can say so
  (`world drop c<n>`), so the trace format moved to version 2.
- **Shared code with the client: none.** The specification marks every
  argument and result layout MISSING. The models answer at the
  procedure level, and requests and answers cross the scheduler's byte
  seam in the simulator's own envelope, which no client crate reads. A
  test fails if `ironafs-sim` depends on a client codec crate.
- **Written by** `claude-code:claude-opus-5-5` (a Claude Code subagent,
  test first).

Left on #96 for the next pull request:

- breaks, resets and probes delivered to the client's callback service,
  forged and dropped;
- callback continuity (assumption A14);
- the model front end that applies epoch advances on its own steps;
- the test strategy's additions.

## Decisions

Made by the controller on the implementer's recommendation:

- **The envelope.** The models keep the simulator's own envelope as their
  byte form until the capture-backed codecs exist. The client will then
  reach them through an adapter written from that revision of the
  specification. No wire layout is invented meanwhile.
- **An unknown server identity.** `vl.get_addrs` for an identity the
  database does not hold answers 363 524, "no such entry", as for an
  unknown volume. The specification names no code for it: its row R24
  makes any code, or any decode failure, mark that one site unusable.
- **`sim.peer_write`.** The second client writes with the simulator's own
  procedure, not an AFS-3 one, because writes are outside the read
  specification.
- **The trace version.** A new kind of line is a change to what a trace
  says, so the version moved to 2, by the rule `VERSION_LINE` states.

## Findings

GLM, round 1:

- **Minor, fixed (`da1cf69`):** origin: pre-existing; kind:
  contract. The change added the `world drop` line but kept the trace
  format at version 1, against the rule `VERSION_LINE`'s comment states.
  - The version is now 2.
  - The golden test failed first against the old fixtures, as did the
    two unit tests that hold the version line literally.
  - The macOS fixtures were regenerated from runs, and differ from the old
    ones in their first line only. The Linux fixtures, byte copies of
    the macOS run, had that line changed to match.
- **Minor, fixed (`8c1535b`):** origin: pre-existing; kind:
  correctness. The cell decoded a request before checking whether its
  server was up. So malformed bytes sent to a down or absent server got a
  marshalling abort, where the module's contract says such a server drops
  everything.
  - The destination is now read first, and bytes to a server that is not
    there are dropped unread.
  - Its test failed first.

Of GLM's seven uncertain items:

- Two led to changes (`4149f19`, `e9ac183`):
  - The envelope's list counts now use each item's least encoded size.
  - The 32-bit fetch in the boundary scenario now ends at 2³¹ − 1, the
    last range a client may send (5.5, point 2), not at 2³¹.
- Three were answered and documented in the code (`4149f19`):
  - a bulk fault's index past the reply's last item plants nothing;
  - a short bulk reply still leaves the server holding a promise for
    every file asked;
  - which breaks a write owes is the simulator's own design, since the
    callback specification states only the client's service.
- One was settled by the trace-version decision above.
- One noted the lane could not run the tests. The evidence below covers
  that.

The review stopped there, under the stop rule: only minor findings, fixed
and recorded, so no verification round.
