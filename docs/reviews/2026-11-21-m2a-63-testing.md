# Review record: the test strategy

## The change

Class P. Issue #63 (plan id M2a-76).

- `docs/specs/testing.md`: a procedure. The test obligations each kind
  of code carries (decoders, pure state machines, seams and drivers, the
  composition, OS layers, the CLI, durable formats, security properties,
  concurrency); how the suite grows by construction; how each test
  category shows it can fail; the inventory ratchet; no retries and the
  flaky-test rule; the replay and trace rules; the generator's form; the
  tiers with their budgets and venues; how scheduled failures are
  classified and reported; phase-gate evidence; counted and timed
  benchmarks; and the layout for pure crates.
- `docs/specs/README.md`: the index row, and register rows E38 to E47 for
  the outside pages the procedure cites.
- **Written by** `claude-code:claude-opus-5-5` (drafting, and the fixes
  of every round).

## Inputs

- The owner's decisions listed in issue #63, recorded in the
  specification's section 1 and cited where each applies.
- Decision 11 (no seed, input or replay command published from scheduled
  jobs) is applied strictly, as the owner decided it: a scheduled job
  uploads no artefact and puts nothing a test produced or read in a
  cache, encrypted or not, since ciphertext on a public repository is
  still published. This settles the drafted option of an encrypted
  fuzz-crash payload, which the specification does not take.

## Findings

Round 1:

- **Major, fixed:** the phase-gate obligations issue #63 assigns to
  M2a-50 (the inventory, coverage and mutation reports attached, and a
  census of every seam and ban) were missing, and S1's rule that a
  conformance body run against every implementation had no mechanism.
  5.5, point 10 now sets the phase-gate evidence and an `xtask` census of
  every seam trait's implementations and callers with their S1 and S2
  runs, and of every Clippy ban with the planted call that fires it; a
  disagreement amends the specification or the code before the gate. S1
  takes its implementation set from the census. Section 10 adds the
  census's failure tests.
- **Major, fixed:** the inventory failed every pull-request job on a venue
  test (L3, L4, F5; O49, points 4 and 5) that compiles on a hosted target
  but runs elsewhere, since only a quarantined test could be skipped.
  Each inventory entry now carries a tier and venue tag from 5.5's closed
  set; a job reconciles only its own tier and venue; the venue's manifest
  fails unless every entry tagged for it ran and passed; an unknown tag
  fails; sharded runs reconcile over the union of shards. `cargo xtask
  inventory update` covers the host's listable targets and prints the
  lines for the others. Section 10 adds four inventory tests.
- **Major, fixed:** scheduled jobs' rules contradicted each other. The
  weekly fuzz corpus was carried in the default branch's Actions cache,
  which a pull request's workflow can restore (E43, read at source); a
  digest of a short input can be reversed by enumeration; and the
  flaky-test issue required the seed. Applied under the owner's strict
  decision 11: until M4 every scheduled fuzz run starts from tracked
  seeds and its working corpus ends with the runner; no artefact and no
  cache from a scheduled job, encrypted or not; no digest; a failing fresh
  seed is kept nowhere until M4, and the maintainer reproduces from the
  target and revision. The reviewer's proposed fix (a reproducer
  encrypted to a checked-in key, and a keyed digest) was not taken: it
  contradicts that decision.
- **Major, fixed:** nothing checked that pure crates' unit tests in `src/`
  name no `std` path and use only `Property` and `Source` from
  `ironafs-test-support`, since a library build skips `cfg(test)` code.
  5.1 adds an `xtask` check over every file in a pure crate's `src/`,
  test modules included, with planted-violation tests in section 10. The
  reviewer's statement that the test build injects `std` was not verified
  and is not claimed.
- **Major, fixed:** the ordinary-failure list was keyed by test binary or
  scenario, which hold restricted and ordinary checks together, and a
  test assertion and a panic in code under test both fail by panicking.
  The list now names exact test names or invariant ids; the checks write
  a structured failure record naming the check before failing; a listed
  test failing with no record, or another check's record, is restricted.
  The record's encoding is left to #75.
- **Major, fixed:** three gaps in "can it fail" evidence. 5.4, point 1
  gains rows for fuzz targets, seam conformance bodies and published
  conformance corpora; section 9's O45, point 6 row now rests on the fuzz
  manifest check rather than freshness; 5.5, point 11 adds a pull-request
  workflow check (hosted runner labels only, no timed benchmark), with
  tests in section 10.
- **Major, fixed:** several outside-tool claims had no registered page,
  and E40 named the default branch's README rather than the pinned
  version's. Read at source and registered: E40 at tag v0.9.1, E41 and E43
  re-read and extended, and new rows E44 (libFuzzer), E45 (nextest), E46
  (GitHub concurrency) and E47 (GitHub's workflow runs API). Claims no
  page confirmed were reworded instead: the fuzz directories are explicit
  paths the runner passes, and the build-cache rule rests on the
  workspace lints (rule 5), marked as the project's own.
- **Minor, fixed:** some crates had no coverage table. 5.4, point 3 now
  names table 1's crates, puts the rest in the report-only table, and
  `cargo xtask coverage` fails on a crate in no table or in two.
- **Minor, fixed:** the generated tests assumed a decoder for every
  message, though `ironafs-events` may be encode-only. Decoder checks are
  scoped to messages with a generated decoder; an encode-only message
  gets D4 on the encoder and, when it bears a secret, D8.
- **Minor, fixed:** timed-out mutants had no rule (now their own count,
  handled like survivors); pull-request mutation over the diff is report
  only, with a section 11 trigger to promote it; N1 states how tests claim
  refusal case ids (`tests/refusal-cases.txt`); and section 10 gains the
  missing self-tests.

Gemini also listed what it could not check in round 1. One item became
open question Q3 (below). The rest were the cited repository sections and
outside pages it was not given, GitHub state, and the checks it could not
run; the cited ADR 0004 points the findings rested on were re-read at
source, and `cargo xtask check` passed on the fixed tree.

Round 2:

- **Minor, fixed:** 5.5, point 9 still listed "timed out", "simulator
  error" and "could not run" as ordinary failure kinds, though none of

- **Minor, fixed:** 5.3, point 2 required D3 both ways for every message
  with a generated decoder, while the census allows decode-only messages.

## Follow-ups for #75

Issue #75's brief predates the strict reading of decision 11 and needs a
comment, linked from this specification's pull request, so that it:

- drops the encrypted fuzz-crash upload, the owner's public key file and
  the choice of encryption tool;
- drops the digest of a restricted result: a restricted result leaves only
  the job, the target, the revision and the class;
- replaces the uploaded result file with a handoff to the reporter that
  creates no artefact;
- takes the failure kinds "assertion failed" and "invariant violated",
  and treats a listed test that timed out or could not run as restricted;
- defines the structured failure record's encoding (5.5, point 9);
- settles Q3.
